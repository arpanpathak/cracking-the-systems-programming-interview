Interview preparation for senior cloud and systems engineering roles. Five parts,
each one runnable on its own.

| Part | Contents | Start with |
|---|---|---|
| [`rust-interview-lab/`](rust-interview-lab/) | 31 Rust library modules and 22 standalone programs: graphs, trees, caches, concurrency primitives built from scratch, a hand-rolled async runtime, an epoll server, TCP and HTTP servers. Every module carries its own unit tests. | `cd rust-interview-lab && cargo test` |
| [`rust-interview-lab/benchmarking_examples/`](rust-interview-lab/benchmarking_examples/) | Two caches and four linked lists, the programs that measure them, captured output in `BENCHMARKS.md`, and an 8-page report as a PDF. | `cd rust-interview-lab && cargo run --release --bin benchmark` |
| [`operator/`](operator/) | Kubebuilder v4 layout on controller-runtime. The `GpuWorkload` API type and the reconciler are hand-written; the CRD and deepcopy code is generated by controller-gen. | `cd operator && go test ./...` |
| [`docs/`](docs/) | 14 study guides: Linux internals, Kubernetes, controller-runtime, CLI/SDK/REST design, concurrency and async, testing and CI, behavioural rounds, and a three-part Rust guide. | read, or `rg` them |
| [`cracked-rustaceans-book/`](cracked-rustaceans-book/) | 34 chapters, one per source file. Each gives the problem statement, the design, the code, a worked example, the cost of every operation, and the inputs the code does not survive. | `make pdf` |
| [`scripts/`](scripts/) | Kind cluster setup, plus a live end-to-end check of the operator. | `scripts/verify-kind.sh` |

## Quick start

### Rust lab

```bash
cd rust-interview-lab
cargo test                       # library and program unit tests
cargo run --bin count_islands    # or ll, shadowing, mutex_poisoning, ...
cargo run --bin os_paging        # or os_scheduler, net_ipv4, cs_fib, ...
cargo run --release --bin syscall_overhead
```

### Benchmarks and the report

```bash
cd rust-interview-lab
cargo run --release --bin benchmark            # cache, then all four list variants
cargo run --release --bin benchmark cache      # index arena against Rc<RefCell> list
cargo run --release --bin benchmark list       # the four linked-list variants
cargo run --release --bin list_drop            # 5,000,000 nodes, freed iteratively
python3 benchmarking_examples/build_report_pdf.py   # rebuild the report
```

Recorded output is in [`BENCHMARKS.md`](rust-interview-lab/BENCHMARKS.md), and the
report is at
[`benchmarking-report.pdf`](rust-interview-lab/benchmarking_examples/benchmarking-report.pdf).

### Go operator

```bash
cd operator
go test ./...
```

### Live Kubernetes check

`scripts/verify-kind.sh` creates a Kind cluster, installs the CRD, starts the manager,
applies a sample `GpuWorkload`, and waits for the Deployment to roll out. The rollout
is the assertion: if reconciliation is broken, the wait times out.

```bash
scripts/verify-kind.sh
scripts/cleanup-kind.sh          # optional
```

> The Kind sample sets `gpuCount: 0`, because Kind nodes have no GPU and no device
> plugin, so the pod would stay `Pending` forever. On a real GPU cluster set
> `gpuCount: 1` and `runtimeClassName: nvidia`, as in
> `operator/config/samples/gpucloud_v1_gpuworkload_gpu.yaml`.

### Book

```bash
cd cracked-rustaceans-book
make pdf                         # -> build/cracked-rustaceans.pdf
make html                        # -> book/
```

The printed edition is committed at
[`cracked-rustaceans-book/build/cracked-rustaceans.pdf`](cracked-rustaceans-book/build/cracked-rustaceans.pdf).

## What the Rust lab covers

| Topic | File | Idea it tests |
|---|---|---|
| Two sum | `two_sum.rs` | Precompute the complement instead of searching for it |
| Valid parentheses | `valid_parentheses.rs` | Unmatched openers need order, not a count, so a stack |
| Min stack | `min_stack.rs` | Amortise the minimum over pushes instead of rescanning |
| Sliding window | `sliding_window.rs` | The window start only moves forward, so the scan is linear |
| Merge intervals | `merge_intervals.rs` | Sort by start, then extend or append against the last interval |
| Top k frequent | `top_k_frequent.rs` | A bounded heap beats sorting the whole input |
| Binary tree | `binary_tree.rs` | `enum Tree` makes the empty case a variant, not a null |
| Binary search tree | `bst_clean.rs` | The ordering invariant decides which subtree to recurse into |
| Binary search | `binary_search.rs` | A half-open range and a sorted-half test |
| Trie | `trie.rs` | Share prefixes as edges, so lookup costs the key length |
| Topological sort | `graph_topology.rs` | Kahn's algorithm, and a short output means a cycle |
| Coin change | `dp.rs` | `Option<i32>` instead of a `-1` sentinel |
| Subsets | `backtracking.rs` | One `push` and one `pop` around each recursive call |
| Reverse linked list | `linked_list.rs` | Three bindings and no allocation |
| LRU cache | `lru_cache.rs` | `HashMap` for lookup, `VecDeque` for recency |
| Rate limiter | `rate_limiter.rs` | Refill from elapsed time, so the bucket needs no timer |
| Worker pool | `worker_pool.rs` | Bounded workers, results collected by index to keep order |
| Workload state machine | `state_machine.rs` | Legal transitions as one exhaustive `match` |
| Typed API errors | `state_machine.rs` | `is_retryable()` without parsing a message |

## What the systems lab adds

The second half of the lab moves from puzzles to the machinery the role is about:
concurrency primitives written out by hand, async without a runtime, and the
network stack from raw TCP to HTTP request framing.

| Topic | File | Idea it tests |
|---|---|---|
| Lifetime of a spawned thread | `threads.rs` | `thread::scope` borrows instead of requiring `'static` |
| Atomic state | `threads.rs` | `Ordering` is part of the contract, not a detail |
| Spin lock from scratch | `spin_lock.rs` | `compare_exchange_weak`, acquire/release, RAII guard |
| Counting semaphore | `semaphore.rs` | `Mutex` plus `Condvar`, and a guard that cannot leak a permit |
| Bounded MPMC queue | `bounded_queue.rs` | Backpressure, and a `close()` that wakes every waiter |
| Lock-free SPSC ring | `ring_buffer.rs` | A release store publishes, an acquire load consumes |
| Sharded cache | `sharded_cache.rs` | Per-shard locks trade memory for less contention |
| Retry policy | `retry.rs` | Exponential backoff with full jitter, and a `Retry-After` floor |
| Consistent hashing | `consistent_hash.rs` | Virtual nodes keep remapping small when a node leaves |
| Bump allocator | `bump_allocator.rs` | Alignment arithmetic, and why reset costs nothing |
| HTTP/1.1 parsing | `http_request.rs` | `Content-Length` against chunked, and the smuggling checks |
| Async from first principles | `async_mini.rs` | `Future`, `Waker`, `Pin`, and a task queue that runs them |
| Threading and async in practice | `docs/14` | The same material as a study guide, with the failure modes |
| Server implementations | `src/bin/tcp_echo_server.rs`, `http_server.rs`, `epoll_echo.rs` | Thread per connection, keep-alive, and readiness-based I/O |

## Benchmarks

`benchmarking_examples/` holds the structures and the programs that measure them.
Two caches and four linked lists are compared on the same workload, and every
number in the report was produced by these programs.

| Question | Where |
|---|---|
| Index arena against `Rc<RefCell>` nodes for an LRU | `cache/arena.rs`, `cache/rc_list.rs` |
| Four ways to store and free a singly linked list | `lists/boxed.rs`, `enum_node.rs`, `boxed_drop.rs`, `enum_drop.rs` |
| Where the recursive free stops working | about 265,000 nodes on an 8 MiB stack |
| How the measurements are taken | warm-up, then the fastest of three passes |
| Captured output and the written report | `BENCHMARKS.md`, `benchmarking-report.pdf` |
