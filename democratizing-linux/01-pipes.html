Democratizing Linux: A Pipe Dream

Pipes

A pipe is a one-way stream of bytes between processes, buffered in a fixed amount of kernel memory. The shell creates one for each | on a command line. In seq 1 100000 | grep 7 | wc -l, the first pipe carries the output of seq to the input of grep, and the second carries the output of grep to the input of wc.

In this chapter, we will specify what a pipe has to do, measure how the Linux pipe behaves, and then implement the same design ourselves. We will write pipefacts, which measures a kernel pipe, handpipe, which implements a pipe in user space with the kernel’s data structure, and pipeline, which connects real commands with kernel pipes the way a shell does. Each program is written in Go and in Rust.

This chapter covers

  • the requirements of a byte stream between processes, and the mechanism that meets each
  • the capacity of a Linux pipe and the unit in which a read frees space
  • the pipe buffer: a ring of pages indexed by the counters head and tail
  • blocking: how a full buffer suspends the writer and an empty buffer suspends the reader
  • end of stream and SIGPIPE: how each side learns that the other has closed
  • the descriptor rule a program must follow when it builds a pipeline
  • the kernel’s struct pipe_inode_info and struct pipe_buffer
  • resizing a pipe, named pipes, and how to inspect pipes on a running system

Why a pipe

Consider the job of counting how many of the numbers from 1 to 100000 contain the digit 7. seq 1 100000 prints the numbers, 588895 bytes of text, and grep 7 | wc -l counts the matching lines. The output of the first program has to reach the second somehow.

The obvious way is a temporary file: run seq and store its output, then run grep on the file. This works, and it has 3 costs. The whole output is stored, although each number is needed only once. The second program cannot start until the first has finished. And if the output were endless, as it is for a program that follows a log, the method would not work at all.

A pipe removes all 3. It is a small buffer in memory with a writer on one side and a reader on the other. The writer adds bytes, the reader removes them, and both programs run at the same time. The buffer holds 65536 bytes at most, whether 600 kilobytes pass through it or 600 gigabytes.

A small buffer between 2 running programs raises questions that a file does not. What happens when the buffer is full? What happens when it is empty? How does the reader learn that the writer has finished? The answers are the behaviour of a pipe, and the next section lists them as requirements.

Requirements

Linux runs each program as a process, which has its own memory. A process cannot read or write the memory of another. The kernel is the part of the operating system that manages memory and devices for all processes, and a process asks it for a service with a system call: a function call that enters the kernel and returns a result. read and write are system calls. Each takes a file descriptor, a small integer that names an open file or another source of bytes.

Since processes share no memory, a stream of bytes between them has to pass through the kernel. The table lists what such a stream must provide and the mechanism a pipe uses to provide it.

RequirementMechanism in a pipe
Bytes arrive in the order they were senta first-in, first-out buffer
Memory use is independent of the length of the streamthe buffer has a fixed capacity, 16 pages by default
A fast writer cannot overrun a slow readera write to a full buffer blocks until a read frees space
The reader can detect the end of the streama read from an empty buffer returns 0 once every write end is closed
The writer can detect that the reader is gonea write with no read end open raises SIGPIPE and fails with EPIPE

A call blocks when the kernel suspends the calling thread until the call can proceed. A suspended thread consumes no processor time.

The interface

The pipe2 system call creates a pipe and returns a pair of file descriptors: the read end, then the write end. Bytes passed to write on the write end are appended to the pipe’s buffer, and read on the read end removes them from the front.

A pipe has no name in the file system and stores nothing on disk. It exists for as long as some process holds a descriptor for either end. Linux lists the descriptors of a process under /proc/<pid>/fd, where <pid> is the process number, so we can observe a pipe from outside. For sleep 47 | sleep 48, with the processes numbered 4121903 and 4121904, descriptor 1 (standard output) of the first and descriptor 0 (standard input) of the second refer to the same pipe object:

One write, step by step

Before looking at the data structures, we follow a single call. A process holds the write end of a pipe as descriptor 4 and calls write(4, "hello", 5).

  1. The kernel takes entry 4 of the process’s descriptor table and finds a struct file, its record of an open file. The record contains a table of functions, f_op, and for a pipe the write function in that table is pipe_write.
  2. pipe_write locks the pipe. A mutex is a lock that 1 thread can hold at a time, and a thread that asks for a held mutex sleeps until it is released. All further steps happen with the lock held, so a reader running at the same moment sees the pipe either before the write or after it.
  3. It checks that a read end is open. If none is, it sends the process the signal SIGPIPE and returns the error EPIPE.
  4. It looks for room. The bytes can go into the unused end of the page written last, or into a new page if a slot of the buffer is free. If there is no room, the process is put to sleep until a reader makes some, and the step is repeated.
  5. It copies the 5 bytes from the memory of the process into the page.
  6. It wakes any reader that is asleep waiting for data, releases the lock, and returns 5.

Each step corresponds to a field of the structure that represents a pipe in the kernel.

// block is the size of every write the program attempts: one page.
const block = 4096

// newPipe creates a pipe in non-blocking mode: a read or a write that cannot
// proceed returns EAGAIN where it would otherwise suspend the caller.
func newPipe() (reader, writer int, err error) {
	var fds [2]int

	if err := unix.Pipe2(fds[:], unix.O_NONBLOCK|unix.O_CLOEXEC); err != nil {
		return 0, 0, fmt.Errorf("pipe2: %w", err)
	}

	return fds[0], fds[1], nil
}

fill measures free space. It writes 4096-byte blocks until a write returns EAGAIN and returns the total number of bytes accepted. drain removes bytes.

Listing 1.5 Measuring free space by writing until the kernel refuses, in Go. code/go/pipefacts/main.go

// fill writes whole blocks until the kernel refuses one and returns the
// number of bytes accepted.
func fill(writer int) (int, error) {
	data := make([]byte, block)
	total := 0

	for {
		n, err := unix.Write(writer, data)

		if errors.Is(err, unix.EAGAIN) {
			return total, nil
		}

		if err != nil {
			return total, fmt.Errorf("write: %w", err)
		}

		total += n
	}
}

// drain reads and discards up to n bytes.
func drain(reader, n int) error {
	_, err := unix.Read(reader, make([]byte, n))

	return err
}

Listing 1.6 Measuring free space by writing until the kernel refuses, in Rust. code/rust/pipefacts/src/main.rs

/// Writes whole blocks until the kernel refuses one and returns the number of
/// bytes accepted.
fn fill(writer: &OwnedFd) -> nix::Result<usize> {
    let data = [0u8; BLOCK];
    let mut total = 0;

    loop {
        match write(writer, &data) {
            Ok(n) => total += n,
            Err(Errno::EAGAIN) => return Ok(total),
            Err(error) => return Err(error),
        }
    }
}

/// Reads and discards up to `n` bytes.
fn drain(reader: &OwnedFd, n: usize) -> nix::Result<usize> {
    read(reader, &mut vec![0u8; n])
}

// resize changes the capacity of a pipe with fcntl and measures it after
// each change.
func resize() error {
	reader, writer, err := newPipe()

	if err != nil {
		return err
	}

	defer unix.Close(reader)
	defer unix.Close(writer)

	for _, request := range []int{4 * block, 5000, 1 << 20} {
		granted, err := unix.FcntlInt(uintptr(writer), unix.F_SETPIPE_SZ, request)

		if err != nil {

		}

		if err != nil {
			return err
		}

		fmt.Printf("capacity of %d bytes requested: %d granted, %d bytes accepted\n", request, granted, accepted)

		if err := drain(reader, accepted); err != nil {
			return err
		}
	}

	return nil
}

The buffer: a ring of pages

The kernel allocates physical memory in pages, and the pipe buffer is built from that unit. A pipe has an array of slots, 16 by default, and each slot refers to a page. Each slot also records which part of its page holds unread data: an offset to the first unread byte and a length.

Since the buffer is built from page references, an empty pipe needs no data pages and an idle pipe costs little memory. A page that already contains the data can also be placed in a slot directly: the splice system call moves page references between a file and a pipe and copies no bytes.

The slots are used as a ring, indexed by the counters head and tail:

  • head is the number of pages added to the ring since the pipe was created.
  • tail is the number of pages removed.

head and tail only increase. The ring maintains these invariants:

  1. head - tail is the number of pages in use, and it is between 0 and the number of slots.
  2. Counter value c refers to slot c mod slots. The oldest page is at tail and the newest at head - 1.
  3. New bytes are appended to the newest page if it has unused space after its data. The remainder goes into new pages at head.
  4. Bytes are removed from the oldest page. When its length reaches 0, the page is released and tail advances by 1.

The kernel computes the slot with a mask in place of a division: head & (ring_size - 1). The 2 are equal when ring_size is a power of 2, which is the reason a request for 5000 bytes was rounded up to 2 slots. The counters are unsigned 32-bit numbers and wrap around to 0 after about 4 billion pages. head - tail remains correct across the wrap, because unsigned subtraction wraps in the same way.

Invariants 3 and 4 explain the measurement. Removing bytes from the oldest page frees space at the front of that page, and invariant 3 places no new bytes there. The space becomes usable only when the whole page is released.

// A page is one slot of the ring: a block of memory, and the position and
// length of the bytes in it that have not been read yet.
type page struct {
	data   []byte
	offset int
	length int
}

// A ring is the storage of a pipe. head counts the pages ever put into use
// and tail counts the pages ever emptied, so head-tail pages are in use, and
// a counter's remainder after division by the number of slots is its slot.
type ring struct {
	pages []page
	head  uint
	tail  uint
}

func newRing(slots, pageSize int) *ring {
	pages := make([]page, slots)

	for i := range pages {
		pages[i].data = make([]byte, pageSize)
	}

	return &ring{pages: pages}
}

func (r *ring) empty() bool {
	return r.head == r.tail
}

func (r *ring) full() bool {
	return r.head-r.tail == uint(len(r.pages))
}

// slot returns the page that a counter refers to.
func (r *ring) slot(counter uint) *page {
	return &r.pages[counter%uint(len(r.pages))]
}

/// One slot of the ring: a block of memory, and the position and length of
/// the bytes in it that have not been read yet.
struct Page {
    data: Vec<u8>,
    offset: usize,
    length: usize,
}

/// The storage of a pipe. `head` counts the pages ever put into use and
/// `tail` counts the pages ever emptied, so `head - tail` pages are in use,
/// and a counter's remainder after division by the number of slots is its
/// slot.
struct Ring {
    pages: Vec<Page>,
    head: usize,
    tail: usize,
}

impl Ring {

        let pages = (0..slots)
            .map(|_| Page {
                data: vec![0; page_size],
                offset: 0,
                length: 0,
            })
            .collect();

        Ring {
            pages,
            head: 0,
            tail: 0,
        }
    }

    fn empty(&self) -> bool {
        self.head == self.tail
    }

    fn full(&self) -> bool {
        self.head - self.tail == self.pages.len()
    }

    /// The page that a counter refers to.
    fn slot(&mut self, counter: usize) -> &mut Page {
        let slots = self.pages.len();

        &mut self.pages[counter % slots]
    }
}

put implements invariant 3: first the unused space of the newest page, then free slots. It returns the number of bytes copied, which is smaller than the request when the ring fills.

Listing 1.19 Appending bytes to the ring, in Go. code/go/handpipe/main.go

// put copies as much of data as the ring has room for and returns the number
// of bytes it copied. The bytes go first into the unused end of the newest
// page, then into free slots, one page each.
func (r *ring) put(data []byte) int {
	copied := 0

	if !r.empty() {
		newest := r.slot(r.head - 1)
		end := newest.offset + newest.length

		n := copy(newest.data[end:], data)
		newest.length += n
		copied += n
	}

	for copied < len(data) && !r.full() {
		next := r.slot(r.head)
		next.offset = 0
		next.length = copy(next.data, data[copied:])

		copied += next.length
		r.head++
	}

	return copied
}

take implements invariant 4. It advances offset in the oldest page and increments tail when the page is exhausted.

Listing 1.21 Removing the oldest bytes from the ring, in Go. code/go/handpipe/main.go

// take moves up to len(buf) of the oldest bytes into buf and returns the
// number it moved. A slot becomes free when the last byte of its page has
// been taken.
func (r *ring) take(buf []byte) int {
	moved := 0

	for moved < len(buf) && !r.empty() {
		oldest := r.slot(r.tail)

		n := copy(buf[moved:], oldest.data[oldest.offset:oldest.offset+oldest.length])
		oldest.offset += n
		oldest.length -= n
		moved += n

		if oldest.length == 0 {
			r.tail++
		}
	}

	return moved
}

Blocking

The ring is a single-threaded data structure. A pipe adds safe access from a reader and a writer running concurrently, and a defined behaviour when a call cannot make progress. Figure 1.7 lists the cases of each call.

The blocking cases provide flow control. If seq produces output faster than grep consumes it, the ring fills and seq is suspended inside write. When grep releases a page, seq resumes. The writer’s rate is therefore limited to the reader’s rate, and the memory between them stays at 16 pages for a stream of any length. Neither program contains code for this; it follows from the semantics of write.

In addition to the ring, the implementation needs:

  • A lock, which gives a thread exclusive access to the ring while it holds the lock.
  • The condition variables readable and writable. A condition variable is a queue on which a thread sleeps until another thread wakes it. Waiting releases the lock and suspends the thread atomically, and reacquires the lock before returning. Readers wait on readable and writers on writable. The kernel’s equivalents are the wait queues rd_wait and wr_wait.
  • The counts readers and writers of the open ends.

write loops until all of data is in the ring. On each pass it checks for a reader, appends what fits, and either wakes the readers or waits on writable.

A woken thread must test its condition again before proceeding. A wake-up indicates that the state changed, and the change may be unrelated to the condition the thread waits for: in row 2 of the trace, a take of 3 bytes freed no slot. For this reason the wait is inside the loop, and the writer calls put again after every wake-up.

// write returns when every byte of data is in the ring, or when no reader is
// left. While the ring is full it sleeps on writable.
func (p *pipe) write(data []byte) (int, error) {
	p.mu.Lock()
	defer p.mu.Unlock()

	written := 0

	for written < len(data) {
		if p.readers == 0 {
			return written, errBrokenPipe
		}

		n := p.ring.put(data[written:])
		written += n

		if n == 0 {
			p.writable.Wait()
			continue
		}

		p.readable.Broadcast()
	}

	return written, nil
}

impl Pipe {
    /// Returns when every byte of `data` is in the ring, or when no reader is
    /// left. While the ring is full it sleeps on `writable`.
    fn write(&self, data: &[u8]) -> Result<usize, BrokenPipe> {
        let mut state = self.state.lock();
        let mut written = 0;

        while written < data.len() {
            if state.readers == 0 {
                return Err(BrokenPipe);

            let n = state.ring.put(&data[written..]);
            written += n;

                continue;

The end of a stream

The counts change when an end is opened or closed, and “closed” has a precise meaning. An end of a pipe is a struct file, and several descriptors can refer to the same struct file: dup creates another one, and fork gives the child a copy of every descriptor of the parent. The kernel releases the struct file, and lowers readers or writers, when the last of those descriptors is closed. A single forgotten descriptor in any process keeps the end open.

Building a pipeline

pipeline runs seq 1 100000 | grep 7 | wc -l with kernel pipes. The kernel’s rules for descriptors determine how it must manage them.

  1. Descriptors are inherited. When a process (the parent) starts another (the child), the child receives copies of the parent’s descriptors. A copy refers to the same pipe end as the original.
  2. An end is closed when its last descriptor is closed. The kernel counts the descriptors that refer to each end. read returns 0 only when the count for the write end is 0.

Suppose the parent creates a pipe, starts seq with the write end and grep with the read end, and keeps its own descriptors open. When seq exits, the write end still has an open descriptor, the parent’s. grep then blocks in read indefinitely and the pipeline does not finish. The rule for the parent follows: after starting a child, close the parent’s copy of every pipe end that was passed to it.

O_CLOEXEC enforces the same rule for descriptors that were not passed deliberately. The kernel closes a descriptor carrying this flag when the process executes a new program. Go’s os.Pipe and Rust’s io::pipe both set it, so each command receives its own ends and no descriptors for the other pipes.

start creates a pipe for each command. Each command writes to its own pipe and reads from the previous pipe, and the read end of the newest pipe is carried to the next iteration. The parent’s copies are closed in each iteration: explicitly in Go, and in Rust by ownership, since the ends are moved into the Command, which is dropped at the end of the statement.

// start runs the commands of a pipeline. Command i writes to pipe i and reads
// from pipe i-1; the first command reads /dev/null. It returns the commands
// and the read end of the last pipe.
func start(stages [][]string) ([]*exec.Cmd, *os.File, error) {
	var input *os.File
	commands := make([]*exec.Cmd, 0, len(stages))

	for _, stage := range stages {
		reader, writer, err := os.Pipe()

		if err != nil {
			return nil, nil, err
		}

		command := exec.Command(stage[0], stage[1:]...)
		command.Stdout = writer

		if input != nil {
			command.Stdin = input
		}

		err = command.Start()

		// The child holds its own copies of both ends. Closing the parent's
		// copies leaves the child's as the only ones.
		writer.Close()

		if input != nil {
			input.Close()
		}

		if err != nil {
			reader.Close()

			return nil, nil, fmt.Errorf("%s: %w", stage[0], err)
		}

		commands, input = append(commands, command), reader
	}

	return commands, input, nil
}

/// and the read end of the last pipe.
fn start(stages: &[Vec<&str>]) -> io::Result<(Vec<Child>, PipeReader)> {
    let mut input = None;
    let mut children = Vec::with_capacity(stages.len());

    for stage in stages {
        let (reader, writer) = io::pipe()?;
        let stdin = input.take().map_or_else(Stdio::null, Stdio::from);

        // The `Command` owns the parent's copies of both ends. It is dropped
        // when this statement ends, which closes them and leaves the child's
        // copies as the only ones.
        let child = Command::new(stage[0])
            .args(&stage[1..])
            .stdin(stdin)
            .stdout(writer)
            .spawn()?;

        children.push(child);
        input = Some(reader);
    }

    let output = input.ok_or(io::ErrorKind::InvalidInput)?;

    Ok((children, output))
}

Named pipes

The pipes so far have no name, so only processes that inherited the descriptors can use them. A named pipe, or FIFO, is the same kernel object with an entry in the file system, created by mkfifo. Unrelated processes open it by path, one for writing and one for reading, and the bytes pass through a struct pipe_inode_info exactly as before. Nothing is written to the disk. The p at the start of the permissions marks the type.

// block is the size of every write the program attempts: one page.
const block = 4096

// newPipe creates a pipe in non-blocking mode: a read or a write that cannot
// proceed returns EAGAIN where it would otherwise suspend the caller.
func newPipe() (reader, writer int, err error) {
	var fds [2]int

	if err := unix.Pipe2(fds[:], unix.O_NONBLOCK|unix.O_CLOEXEC); err != nil {
		return 0, 0, fmt.Errorf("pipe2: %w", err)
	}

	return fds[0], fds[1], nil
}


// fill writes whole blocks until the kernel refuses one and returns the
// number of bytes accepted.
func fill(writer int) (int, error) {
	data := make([]byte, block)
	total := 0

	for {
		n, err := unix.Write(writer, data)

		if errors.Is(err, unix.EAGAIN) {
			return total, nil
		}

		if err != nil {
			return total, fmt.Errorf("write: %w", err)
		}

		total += n
	}
}

// drain reads and discards up to n bytes.
func drain(reader, n int) error {
	_, err := unix.Read(reader, make([]byte, n))

	return err
}


// capacity fills a pipe when it is new, after 1 byte has been read, and
// after 4096 bytes have been read. Each fill reports the free space.
func capacity() error {
	reader, writer, err := newPipe()

	if err != nil {
		return err
	}

	defer unix.Close(reader)
	defer unix.Close(writer)

	steps := []struct {
		read   int
		report string
	}{
		{0, "new pipe: %d bytes accepted\n"},
		{1, "after reading 1 byte: %d bytes accepted\n"},
		{block - 1, "after reading 4096 bytes in total: %d bytes accepted\n"},
	}

	for _, step := range steps {
		if err := drain(reader, step.read); err != nil {
			return err
		}

		accepted, err := fill(writer)

		if err != nil {
			return err
		}

		fmt.Printf(step.report, accepted)
	}

	return nil
}


// resize changes the capacity of a pipe with fcntl and measures it after
// each change.
func resize() error {
	reader, writer, err := newPipe()

	if err != nil {
		return err
	}

	defer unix.Close(reader)
	defer unix.Close(writer)

	for _, request := range []int{4 * block, 5000, 1 << 20} {
		granted, err := unix.FcntlInt(uintptr(writer), unix.F_SETPIPE_SZ, request)

		if err != nil {
			return fmt.Errorf("F_SETPIPE_SZ: %w", err)
		}

		if err != nil {
			return err
		}

		if err := drain(reader, accepted); err != nil {
			return err
		}
	}

	return nil
}

use nix::fcntl::{FcntlArg, OFlag, fcntl};
use nix::unistd::{pipe2, read, write};

/// The size of every write the program attempts: one page.
const BLOCK: usize = 4096;

/// Creates a pipe in non-blocking mode: a read or a write that cannot proceed
/// returns `EAGAIN` where it would otherwise suspend the caller. The read end
/// is first.
fn new_pipe() -> nix::Result<(OwnedFd, OwnedFd)> {
    pipe2(OFlag::O_NONBLOCK | OFlag::O_CLOEXEC)
}

/// Writes whole blocks until the kernel refuses one and returns the number of
/// bytes accepted.
fn fill(writer: &OwnedFd) -> nix::Result<usize> {
    let data = [0u8; BLOCK];
    let mut total = 0;

    loop {
        match write(writer, &data) {
            Ok(n) => total += n,
            Err(Errno::EAGAIN) => return Ok(total),
            Err(error) => return Err(error),
        }
    }
}

/// Reads and discards up to `n` bytes.
fn drain(reader: &OwnedFd, n: usize) -> nix::Result<usize> {
    read(reader, &mut vec![0u8; n])
}

/// Fills a pipe when it is new, after 1 byte has been read, and after 4096
/// bytes have been read. Each fill reports the free space.
fn capacity() -> nix::Result<()> {
    let (reader, writer) = new_pipe()?;

    let steps = [
        (0, "new pipe"),
        (1, "after reading 1 byte"),
        (BLOCK - 1, "after reading 4096 bytes in total"),
    ];

    for (count, label) in steps {
        drain(&reader, count)?;

        let accepted = fill(&writer)?;
        println!("{label}: {accepted} bytes accepted");
    }

    Ok(())
}

/// Changes the capacity of a pipe with fcntl and measures it after each
/// change.
fn resize() -> nix::Result<()> {
    let (reader, writer) = new_pipe()?;

    for request in [4 * BLOCK, 5000, 1 << 20] {
        let granted = fcntl(&writer, FcntlArg::F_SETPIPE_SZ(request as i32))?;
        let accepted = fill(&writer)?;

        println!(
            "capacity of {request} bytes requested: {granted} granted, {accepted} bytes accepted"
        );

        drain(&reader, accepted)?;
    }

    Ok(())
}

    if let Err(error) = read(&reader, &mut buf) {

    let n = read(&reader, &mut buf)?;

}

// and a place for a writer to sleep, and a count of the open ends.

// Run it from code/go with:
//
//	go run ./handpipe
package main

import (
	"errors"
	"fmt"
	"strings"
	"sync"
)


// A page is one slot of the ring: a block of memory, and the position and
// length of the bytes in it that have not been read yet.
type page struct {
	data   []byte
	offset int
	length int
}

// A ring is the storage of a pipe. head counts the pages ever put into use
// and tail counts the pages ever emptied, so head-tail pages are in use, and
// a counter's remainder after division by the number of slots is its slot.
type ring struct {
	pages []page
	head  uint
	tail  uint
}

func newRing(slots, pageSize int) *ring {
	pages := make([]page, slots)

	for i := range pages {
		pages[i].data = make([]byte, pageSize)
	}

	return &ring{pages: pages}
}

func (r *ring) empty() bool {
	return r.head == r.tail
}

func (r *ring) full() bool {
	return r.head-r.tail == uint(len(r.pages))
}

// slot returns the page that a counter refers to.
func (r *ring) slot(counter uint) *page {
	return &r.pages[counter%uint(len(r.pages))]
}


// put copies as much of data as the ring has room for and returns the number
// of bytes it copied. The bytes go first into the unused end of the newest
// page, then into free slots, one page each.
func (r *ring) put(data []byte) int {
	copied := 0

	if !r.empty() {
		newest := r.slot(r.head - 1)
		end := newest.offset + newest.length

		n := copy(newest.data[end:], data)
		newest.length += n
		copied += n
	}

	for copied < len(data) && !r.full() {
		next := r.slot(r.head)
		next.offset = 0
		next.length = copy(next.data, data[copied:])

		copied += next.length
		r.head++
	}

	return copied
}


// take moves up to len(buf) of the oldest bytes into buf and returns the
// number it moved. A slot becomes free when the last byte of its page has
// been taken.
func (r *ring) take(buf []byte) int {
	moved := 0

	for moved < len(buf) && !r.empty() {
		oldest := r.slot(r.tail)

		n := copy(buf[moved:], oldest.data[oldest.offset:oldest.offset+oldest.length])
		oldest.offset += n
		oldest.length -= n
		moved += n

		if oldest.length == 0 {
			r.tail++
		}
	}

	return moved
}


// errBrokenPipe is what a write returns when no reader is left.
var errBrokenPipe = errors.New("EPIPE")

// A pipe is a ring shared by a reader and a writer goroutine. readable is where a reader
// sleeps while the ring is empty, and writable is where a writer sleeps while
// the ring is full. readers and writers count the open ends.
type pipe struct {
	mu       sync.Mutex
	readable *sync.Cond
	writable *sync.Cond
	ring     *ring
	readers  int
	writers  int
}

func newPipe(slots, pageSize int) *pipe {
	p := &pipe{ring: newRing(slots, pageSize), readers: 1, writers: 1}
	p.readable = sync.NewCond(&p.mu)
	p.writable = sync.NewCond(&p.mu)

	return p
}


// write returns when every byte of data is in the ring, or when no reader is
// left. While the ring is full it sleeps on writable.
func (p *pipe) write(data []byte) (int, error) {
	p.mu.Lock()
	defer p.mu.Unlock()

	written := 0

	for written < len(data) {
		if p.readers == 0 {
			return written, errBrokenPipe
		}

		n := p.ring.put(data[written:])
		written += n

		if n == 0 {
			p.writable.Wait()
			continue
		}

		p.readable.Broadcast()
	}

	return written, nil
}


// read returns as soon as it has moved at least one byte into buf. While the
// ring is empty and a writer exists it sleeps on readable. It returns 0 when
// the ring is empty and no writer is left: the end of the stream.
func (p *pipe) read(buf []byte) int {
	p.mu.Lock()
	defer p.mu.Unlock()

	for p.ring.empty() && p.writers > 0 {
		p.readable.Wait()
	}

	n := p.ring.take(buf)

	if n > 0 {
		p.writable.Broadcast()
	}

	return n
}


// closeWriter gives up a write end. A reader asleep on an empty ring wakes
// and finds that no writer is left.
func (p *pipe) closeWriter() {
	p.mu.Lock()
	defer p.mu.Unlock()

	p.writers--
	p.readable.Broadcast()
}

// closeReader gives up a read end. A writer asleep on a full ring wakes and
// finds that no reader is left.
func (p *pipe) closeReader() {
	p.mu.Lock()
	defer p.mu.Unlock()

	p.readers--
	p.writable.Broadcast()
}


// picture renders the ring as one cell per slot: the number of unread bytes

}

// transfer sends one megabyte through a pipe of the kernel's size. Byte i of
// the stream has the value i mod 256, which lets the reader verify the order.

	p := newPipe(16, 4096)

	go func() {
		defer p.closeWriter()

		chunk := make([]byte, 100_000)

		for sent := 0; sent < total; sent += len(chunk) {
			chunk = chunk[:min(len(chunk), total-sent)]

			for i := range chunk {
				chunk[i] = byte(sent + i)
			}

			if _, err := p.write(chunk); err != nil {
				return
			}
		}
	}()

	buf := make([]byte, 30_000)
	received, inOrder := 0, true

	for n := p.read(buf); n > 0; n = p.read(buf) {
		for i, b := range buf[:n] {
			inOrder = inOrder && b == byte(received+i)
		}

		received += n
	}

	fmt.Printf("1048576 bytes written: %d bytes read, in order: %v\n", received, inOrder)
	fmt.Printf("write end closed: read returns %d\n", p.read(buf))

	p.closeReader()

	_, err := p.write([]byte("hello"))
	fmt.Printf("read end closed: write fails with %v\n", err)
}

        }
    }

    fn empty(&self) -> bool {
        self.head == self.tail
    }

    fn full(&self) -> bool {
        self.head - self.tail == self.pages.len()
    }

    /// The page that a counter refers to.
    fn slot(&mut self, counter: usize) -> &mut Page {
        let slots = self.pages.len();

        &mut self.pages[counter % slots]
    }
}

/// Copies as many bytes as both slices allow and returns the count.
fn copy(to: &mut [u8], from: &[u8]) -> usize {
    let n = to.len().min(from.len());
    to[..n].copy_from_slice(&from[..n]);

    n
}

impl Ring {
    /// Copies as much of `data` as the ring has room for and returns the
    /// number of bytes it copied. The bytes go first into the unused end of
    /// the newest page, then into free slots, one page each.
    fn put(&mut self, data: &[u8]) -> usize {
        let mut copied = 0;

        if !self.empty() {
            let newest = self.slot(self.head - 1);
            let end = newest.offset + newest.length;

            let n = copy(&mut newest.data[end..], data);
            newest.length += n;
            copied += n;
        }

        while copied < data.len() && !self.full() {
            let next = self.slot(self.head);
            next.offset = 0;
            next.length = copy(&mut next.data, &data[copied..]);

            copied += next.length;
            self.head += 1;
        }

        copied
    }
}

impl Ring {
    /// Moves up to `buf.len()` of the oldest bytes into `buf` and returns the
    /// number it moved. A slot becomes free when the last byte of its page
    /// has been taken.
    fn take(&mut self, buf: &mut [u8]) -> usize {
        let mut moved = 0;

        while moved < buf.len() && !self.empty() {
            let oldest = self.slot(self.tail);
            let unread = oldest.offset..oldest.offset + oldest.length;

            let n = copy(&mut buf[moved..], &oldest.data[unread]);
            oldest.offset += n;
            oldest.length -= n;
            moved += n;

            if oldest.length == 0 {
                self.tail += 1;
            }
        }

        moved
    }
}

/// What a write returns when no reader is left.
#[derive(Debug)]
struct BrokenPipe;

impl fmt::Display for BrokenPipe {
    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
        f.write_str("EPIPE")
    }
}

/// What the lock guards: the ring and the count of the open ends.
struct State {
    ring: Ring,
    readers: usize,
    writers: usize,
}

/// A ring shared by a reader and a writer thread. `readable` is where a reader sleeps while
/// the ring is empty, and `writable` is where a writer sleeps while the ring
/// is full.
struct Pipe {
    state: Mutex<State>,
    readable: Condvar,
    writable: Condvar,
}

impl Pipe {
    fn new(slots: usize, page_size: usize) -> Pipe {
        let state = State {
            ring: Ring::new(slots, page_size),
            readers: 1,
            writers: 1,
        };

        Pipe {
            state: Mutex::new(state),
            readable: Condvar::new(),
            writable: Condvar::new(),
        }
    }
}

impl Pipe {
    /// Returns when every byte of `data` is in the ring, or when no reader is
    /// left. While the ring is full it sleeps on `writable`.
    fn write(&self, data: &[u8]) -> Result<usize, BrokenPipe> {
        let mut state = self.state.lock();
        let mut written = 0;

        while written < data.len() {
            if state.readers == 0 {
                return Err(BrokenPipe);
            }

            let n = state.ring.put(&data[written..]);
            written += n;

            if n == 0 {
                self.writable.wait(&mut state);
                continue;
            }

            self.readable.notify_all();
        }

        Ok(written)
    }
}

impl Pipe {
    /// Returns as soon as it has moved at least one byte into `buf`. While
    /// the ring is empty and a writer exists it sleeps on `readable`. It
    /// returns 0 when the ring is empty and no writer is left: the end of the
    /// stream.
    fn read(&self, buf: &mut [u8]) -> usize {
        let mut state = self.state.lock();

        self.readable
            .wait_while(&mut state, |state| state.ring.empty() && state.writers > 0);

        let n = state.ring.take(buf);

        if n > 0 {
            self.writable.notify_all();
        }

        n
    }
}

impl Pipe {
    /// Gives up a write end. A reader asleep on an empty ring wakes and finds
    /// that no writer is left.
    fn close_writer(&self) {
        self.state.lock().writers -= 1;
        self.readable.notify_all();
    }

    /// Gives up a read end. A writer asleep on a full ring wakes and finds
    /// that no reader is left.
    fn close_reader(&self) {
        self.state.lock().readers -= 1;
        self.writable.notify_all();
    }
}

impl Ring {
    /// Renders the ring as one cell per slot: the unread bytes in its page,
    /// or a dot for a free slot.
    fn picture(&self) -> String {
        let slots = self.pages.len();
        let mut cells = vec![".".to_string(); slots];

        for counter in self.tail..self.head {
            cells[counter % slots] = self.pages[counter % slots].length.to_string();
        }

        format!("[{}]", cells.join(" "))
    }
}

/// Applies the calls of the trace to a ring of 4 pages of 8 bytes and prints
/// the ring after each.
fn small_ring() {
    let mut ring = Ring::new(4, 8);
    let mut buf = [0u8; 32];

    let calls = [
        ("put", 12),
        ("take", 3),
        ("put", 30),
        ("take", 5),
        ("put", 30),
    ];

    println!("ring of 4 pages of 8 bytes");

    for (op, n) in calls {
        let done = match op {
            "put" => ring.put(&buf[..n]),
            _ => ring.take(&mut buf[..n]),
        };

        println!(
            "{op:<4} {n:2}: {done:2} bytes   head {}  tail {}   {}",
            ring.head,
            ring.tail,
            ring.picture()
        );
    }
}

/// Puts whole blocks into the ring until it accepts none and returns the
/// number of bytes accepted.
fn fill(ring: &mut Ring, block: &[u8]) -> usize {
    let mut total = 0;

    loop {
        let n = ring.put(block);

        if n == 0 {
            return total;
        }

        total += n;
    }
}

/// Repeats the capacity measurement of pipefacts on a ring with the kernel's
/// dimensions: 16 pages of 4096 bytes.
fn kernel_size() {
    const PAGE_SIZE: usize = 4096;

    let mut ring = Ring::new(16, PAGE_SIZE);
    let mut block = [0u8; PAGE_SIZE];

    let steps = [
        (0, "new pipe"),
        (1, "after reading 1 byte"),
        (PAGE_SIZE - 1, "after reading 4096 bytes in total"),
    ];

    for (count, label) in steps {
        ring.take(&mut block[..count]);

        let accepted = fill(&mut ring, &block);
        println!("{label}: {accepted} bytes accepted");
    }
}

/// Sends one megabyte through a pipe of the kernel's size. Byte `i` of the
/// stream has the value `i` mod 256, which lets the reader verify the order.
fn transfer() {
    const TOTAL: usize = 1 << 20;

    let pipe = Pipe::new(16, 4096);
    let mut buf = vec![0u8; 30_000];

    thread::scope(|scope| {
        scope.spawn(|| {
            let mut chunk = vec![0u8; 100_000];

            for sent in (0..TOTAL).step_by(chunk.len()) {
                chunk.truncate(TOTAL - sent);

                for (i, byte) in chunk.iter_mut().enumerate() {
                    *byte = (sent + i) as u8;
                }

                if pipe.write(&chunk).is_err() {
                    break;
                }
            }

            pipe.close_writer();
        });

        let (mut received, mut in_order) = (0, true);

        loop {
            let n = pipe.read(&mut buf);

            if n == 0 {
                break;
            }

            for (i, byte) in buf[..n].iter().enumerate() {
                in_order = in_order && *byte == (received + i) as u8;
            }

            received += n;
        }

        println!("1048576 bytes written: {received} bytes read, in order: {in_order}");
    });

    println!("write end closed: read returns {}", pipe.read(&mut buf));

    pipe.close_reader();

    if let Err(error) = pipe.write(b"hello") {
        println!("read end closed: write fails with {error}");
    }
}

fn main() {
    small_ring();
    println!();
    kernel_size();
    println!();
    transfer();
}

// Command pipeline runs `a | b | c` the way a shell does: each command's
// standard output is the write end of a pipe, and the next command's standard
// input is the read end of the same pipe.
//
// It runs the pipelines listed in main and prints the last command's output and how each
// command terminated.
//
// Run it from code/go with:
//
//	go run ./pipeline
package main

import (
	"fmt"
	"io"
	"log"
	"os"
	"os/exec"
	"strings"
	"syscall"
)


// start runs the commands of a pipeline. Command i writes to pipe i and reads
// from pipe i-1; the first command reads /dev/null. It returns the commands
// and the read end of the last pipe.
func start(stages [][]string) ([]*exec.Cmd, *os.File, error) {
	var input *os.File
	commands := make([]*exec.Cmd, 0, len(stages))

	for _, stage := range stages {
		reader, writer, err := os.Pipe()

		if err != nil {
			return nil, nil, err
		}

		command := exec.Command(stage[0], stage[1:]...)
		command.Stdout = writer

		if input != nil {
			command.Stdin = input
		}

		err = command.Start()

		// The child holds its own copies of both ends. Closing the parent's
		// copies leaves the child's as the only ones.
		writer.Close()

		if input != nil {
			input.Close()
		}

		if err != nil {
			reader.Close()

			return nil, nil, fmt.Errorf("%s: %w", stage[0], err)
		}

		commands, input = append(commands, command), reader
	}

	return commands, input, nil
}


// ending waits for a command and reports how it terminated: with an exit
// status, or by a signal.
func ending(command *exec.Cmd) string {
	command.Wait()

	state := command.ProcessState

	if status, ok := state.Sys().(syscall.WaitStatus); ok && status.Signaled() {
		return fmt.Sprintf("killed by signal %d", status.Signal())
	}

	return fmt.Sprintf("exited with status %d", state.ExitCode())
}


// run starts a pipeline, reads the last command's output to the end of the
// stream, and prints the output and each command's termination.
func run(line string) error {
	var stages [][]string

	for _, stage := range strings.Split(line, " | ") {
		stages = append(stages, strings.Fields(stage))
	}

	commands, output, err := start(stages)

	if err != nil {
		return err
	}

	defer output.Close()

	text, err := io.ReadAll(output)

	if err != nil {
		return err
	}

	fmt.Println(line)
	fmt.Printf("  output: %s\n", strings.Join(strings.Fields(string(text)), " "))

	for i, command := range commands {
		fmt.Printf("  %s: %s\n", stages[i][0], ending(command))
	}

	return nil
}


func main() {
	for _, line := range []string{"seq 1 100000 | grep 7 | wc -l", "yes | head -n 3"} {
		if err := run(line); err != nil {
			log.Fatal(err)
		}
	}
}

//! Runs `a | b | c` the way a shell does: each command's standard output is
//! the write end of a pipe, and the next command's standard input is the read
//! end of the same pipe.
//!
//! It runs the pipelines listed in main and prints the last command's output and how each
//! command terminated.
//!
//! Run it from code/rust with:
//!
//! ```text
//! cargo run -p pipeline
//! ```

use std::io::{self, PipeReader, Read};
use std::os::unix::process::ExitStatusExt;
use std::process::{Child, Command, Stdio};

/// Runs the commands of a pipeline. Command `i` writes to pipe `i` and reads
/// from pipe `i - 1`; the first command reads /dev/null. Returns the children
/// and the read end of the last pipe.
fn start(stages: &[Vec<&str>]) -> io::Result<(Vec<Child>, PipeReader)> {
    let mut input = None;
    let mut children = Vec::with_capacity(stages.len());

    for stage in stages {
        let (reader, writer) = io::pipe()?;
        let stdin = input.take().map_or_else(Stdio::null, Stdio::from);

        // The `Command` owns the parent's copies of both ends. It is dropped
        // when this statement ends, which closes them and leaves the child's
        // copies as the only ones.
        let child = Command::new(stage[0])
            .args(&stage[1..])
            .stdin(stdin)
            .stdout(writer)
            .spawn()?;

        children.push(child);
        input = Some(reader);
    }

    let output = input.ok_or(io::ErrorKind::InvalidInput)?;

    Ok((children, output))
}

/// Waits for a command and reports how it terminated: with an exit status,
/// or by a signal.
fn ending(child: &mut Child) -> io::Result<String> {
    let status = child.wait()?;

    let text = match (status.signal(), status.code()) {
        (Some(signal), _) => format!("killed by signal {signal}"),
        (None, Some(code)) => format!("exited with status {code}"),
        (None, None) => status.to_string(),
    };

    Ok(text)
}

/// Starts a pipeline, reads the last command's output to the end of the
/// stream, and prints the output and each command's termination.
fn run(line: &str) -> io::Result<()> {
    let stages: Vec<Vec<&str>> = line
        .split(" | ")
        .map(|stage| stage.split_whitespace().collect())
        .collect();

    let (mut children, mut output) = start(&stages)?;

    let mut text = String::new();
    output.read_to_string(&mut text)?;

    let words: Vec<&str> = text.split_whitespace().collect();

    println!("{line}");
    println!("  output: {}", words.join(" "));

    for (stage, child) in stages.iter().zip(&mut children) {
        println!("  {}: {}", stage[0], ending(child)?);
    }

    Ok(())
}

fn main() -> io::Result<()> {
    run("seq 1 100000 | grep 7 | wc -l")?;
    run("yes | head -n 3")
}

Summary

  • A pipe is a one-way byte stream between processes, buffered in kernel memory and reached through a read end and a write end.
  • The buffer is a ring of 16 slots, each referring to one page: 65536 bytes with 4096-byte pages.
  • head counts pages added and tail counts pages removed. Space is released a whole page at a time, when the last byte of the oldest page has been read.
  • A write to a full pipe blocks until a read releases a page. This limits a writer to the rate of its reader and bounds the memory between them.
  • A thread woken from a wait tests its condition again, because a wake-up reports that the state changed and says nothing about which change occurred.
  • read returns 0 when the pipe is empty and no descriptor for the write end remains.
  • write raises SIGPIPE and fails with EPIPE when no descriptor for the read end remains.
  • A program that builds a pipeline closes its own copy of each pipe end after passing it to a child. A copy left open prevents the end of the stream from being reported.
