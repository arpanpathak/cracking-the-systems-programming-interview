A graph G = (V, E) generalizes hierarchical tree topologies by removing both the single-parent restriction and the acyclicity invariant: any vertex in V may connect to any other vertex via an edge in E, and directed or undirected paths may form cycles.

Graphs model arbitrary binary relations across systems engineering, including network routing topologies, distributed cluster communication links, build dependency pipelines, and scheduling constraints. Because multiple paths may converge on the same vertex and cycles can cause non-terminating traversals, every graph traversal algorithm must maintain an explicit visitation state structure, typically a dense Vec<bool>, a HashSet, or a state-machine table backed by a HashMap.

12.1 Graph vocabulary

The fundamental components of a graph are labeled in Figure 12.1.

  • A node (or vertex) represents an entity in the graph.
  • An edge connects two nodes. In a directed graph, an edge has a single orientation from a source node to a target node; in an undirected graph, an edge permits traversal in both directions.
  • The neighbors of a node are the nodes directly reachable via its outgoing edges.
  • A weight is a numeric cost or distance associated with an edge.
  • A path is a sequence of consecutive edges connecting a sequence of nodes.
  • A cycle is a non-empty path that begins and ends at the same node.

A directed graph containing no directed cycles is a directed acyclic graph (DAG). A rooted tree corresponds to the special case of a connected acyclic graph in which every vertex other than the root has indegree 1.

12.2 Storing a graph

The standard in-memory representation of a sparse graph is an adjacency list, which stores each node’s outgoing edges as a collection of (neighbor, weight) pairs. The implementations in this chapter use two variants of the adjacency list (Figure 12.2).

In the index form, nodes are numbered 0..n and the graph has type Vec<Vec<(usize, u32)>>. Looking up the outgoing edges of node i is a single array index graph[i], and visited tracking uses a compact Vec<bool>.

In the map form, nodes may be any hashable type such as string names, and the graph is a HashMap mapping each node to its outgoing edges. Edge lookup hashes the node key, and visited tracking uses a HashSet.

The index form delivers higher throughput and cache locality, whereas the map form is more convenient when nodes carry natural identifiers. Several files in this chapter implement both representations side by side for direct comparison.

The map form in graph_bfs.rs has a type alias:

use std::{
    collections::{HashMap, HashSet, VecDeque},
    hash::Hash,
};

/// Adjacency list keyed by node: each node maps to its `(neighbor, weight)` edges.
pub type GraphAdjList<'a, Node> = HashMap<Node, &'a [(Node, u32)]>;

GraphAdjList<'a, Node> maps each vertex key to a borrowed slice &'a [(Node, u32)] of outgoing (neighbor, weight) pairs. Because the map holds non-owning slice references bounded by lifetime 'a, the backing edge storage must outlive the map itself; in the test suite, edges are backed by 'static constant arrays with program-wide storage duration.

12.3 Breadth-first search

Breadth-first search (BFS) explores vertices in non-decreasing order of unweighted hop distance from a source vertex: first the source at distance 0, then all vertices at distance 1, then distance 2, and so on. Like level-order tree traversal, BFS maintains a FIFO queue representing the active vertex frontier.

Unlike a tree, a general graph may contain multiple distinct paths to the same vertex: in the sample graph, vertex A reaches C directly via (A, C) and indirectly via (A, B, C). Without deduplication, C would be enqueued multiple times. BFS enforces the invariant that each vertex is marked visited immediately upon discovery (when first enqueued), guaranteeing that every reachable vertex enters the frontier at most once.

The upper half of Figure 12.3 traces the frontier queue at each iteration.

12.3.1 BFS with numbered nodes

Listing 12.1 BFS over the index form (lines 18 to 36). src/problems/graph_bfs.rs

/// BFS over an index-based adjacency list. Returns nodes in visiting order.
pub fn bfs_vec(graph: &[Vec<(usize, u32)>], start_node: usize) -> Vec<usize> {
    let mut visited = vec![false; graph.len()];
    let mut queue = VecDeque::from([start_node]);
    let mut result = vec![];

    visited[start_node] = true;

    while let Some(current_node) = queue.pop_front() {
        result.push(current_node);
        for &(neighbor, _) in &graph[current_node] {
            if !visited[neighbor] {
                visited[neighbor] = true;
                queue.push_back(neighbor);
            }
        }
    }
    result
}

The function initializes three structures: visited (one false entry per node), queue (seeded with the start node), and result (collecting nodes in visitation order).

Each iteration dequeues the front node, appends it to result, and inspects its outgoing edges. The pattern &(neighbor, _) destructures each edge pair, copying out the neighbor index while ignoring the weight. Any unvisited neighbor is marked immediately and enqueued at the back.

Because each node enters the queue at most once and every edge is examined once, BFS runs in O(V + E) time, where V is the number of nodes and E is the number of edges. Nodes unreachable from the start never enter the queue and are omitted from the result.

12.3.2 BFS with any node type

Listing 12.2 BFS over the map form (lines 38 to 59).

/// BFS over a `HashMap` adjacency list. Returns nodes in visiting order.
pub fn bfs<Node>(graph: &GraphAdjList<Node>, start_node: Node) -> Vec<Node>
where
    Node: Copy + Eq + Hash,
{
    let mut visited = HashSet::new();
    let mut queue = VecDeque::from([start_node]);
    let mut result = vec![];

    visited.insert(start_node);

    while let Some(current_node) = queue.pop_front() {
        result.push(current_node);
        // slice iter yields &(Node, u32); `&` destructures it
        for &(neighbor, _) in graph[&current_node] {
            if visited.insert(neighbor) {
                queue.push_back(neighbor);
            }
        }
    }
    result
}

The traversal logic is identical, with three structural differences:

  • The function is generic over Node. Its where clause requires Copy so nodes can be copied into the queue and result vector, and Eq + Hash so nodes can serve as keys in HashSet.
  • graph[&current_node] looks up outgoing edges by key. Because indexing a HashMap panics on a missing key, every node in the graph must have an entry, even if its edge slice is empty.
  • visited.insert(neighbor) combines the membership check and insertion in a single call, returning true when the node was previously unseen.

12.4 Depth-first search

Depth-first search (DFS) explores each branch to its full depth before backtracking to alternative edges. Although DFS can be expressed recursively, the implementations below maintain an explicit heap-allocated stack (Vec), avoiding thread call-stack overflow on deep or pathological graphs.

Listing 12.3 DFS over the index form (lines 16 to 33). src/problems/graph_dfs.rs

use std::{collections::HashSet, hash::Hash};

use crate::problems::graph_bfs::GraphAdjList;

/// DFS over an index-based adjacency list. Returns nodes in visiting order.
pub fn dfs_vec(graph: &[Vec<(usize, u32)>], start_node: usize) -> Vec<usize> {
    let mut visited = vec![false; graph.len()];
    let mut stack = vec![start_node];
    let mut result = vec![];

    while let Some(current_node) = stack.pop() {
        if visited[current_node] {
            continue;
        }
        visited[current_node] = true;
        result.push(current_node);
        for &(neighbor, _) in &graph[current_node] {
            stack.push(neighbor);
        }
    }
    result
}

Relative to Listing 12.1, iterative DFS differs in two respects: replacing the FIFO queue with a LIFO stack (pop in place of pop_front), and deferring visitation marking until a vertex is popped rather than when it is pushed.

Deferred marking preserves exact depth-first visitation order at the expense of bounded stack duplication: a vertex reachable via multiple unexpanded edges may appear on the stack more than once (as C and D do in the lower half of Figure 12.3). The stack size remains bounded by O(E), and duplicate entries are discarded immediately via continue upon removal.

Because adjacency entries are pushed in slice order, LIFO extraction explores the final neighbor first: from A, pushing B then C causes C to be expanded before B, yielding the traversal order A, C, D, B.

Listing 12.4 DFS over the map form (lines 35 to 54).

/// DFS over a `HashMap` adjacency list. Returns nodes in visiting order.
pub fn dfs<Node>(graph: &GraphAdjList<Node>, start_node: Node) -> Vec<Node>
where
    Node: Copy + Eq + Hash,
{

    let mut stack = vec![start_node];
    let mut result = vec![];

    while let Some(current_node) = stack.pop() {
        if !visited.insert(current_node) {
            continue;

        for &(neighbor, _) in graph[&current_node] {
            stack.push(neighbor);
        }
    }
    result
}

Here if !visited.insert(current_node) performs atomic membership testing and insertion: a false return value signals that current_node was already visited, prompting the loop to skip the stale stack entry.

The module imports GraphAdjList from crate::problems::graph_bfs so both traversal modules share a single adjacency-list type definition.

12.4.1 A stack of references

When the input topology is a tree, acyclic single-parent connectivity guarantees that no vertex is reachable via multiple paths, eliminating the need for a visited set. The following program performs iterative DFS over an owned tree using a stack of shared references.

Listing 12.5 The complete program. src/bin/rust_interview_hacks_graph.rs

#[derive(Debug)]
struct Node {
    value: i32,
    children: Vec<Node>,
}

fn visit_iter(root: &Node) {
    let mut stack = Vec::<&Node>::from([root]);

    while let Some(node) = stack.pop() {
        println!("{:?}", node);
        // Idiomatic and concise way to extend stack with neighbour iterator
        stack.extend(node.children.iter());
    }
}

fn main() {
    let tree = Node {
        value: 1,
        children: vec![
            Node {
                value: 2,
                children: vec![],
            },
            Node {
                value: 3,
                children: vec![Node {
                    value: 4,
                    children: vec![],
                }],
            },
        ],
    };

    visit_iter(&tree);
    println!("still own it: {}", tree.value); // tree wasn't moved
}

The explicit stack has type Vec<&Node>, storing non-owning references into the tree without moving or cloning any node payloads. Calling stack.extend(node.children.iter()) pushes references to all children in one pass. Accessing tree.value after the traversal terminates verifies that tree retains full ownership throughout.

12.5 A graph with named nodes

Real-world inputs frequently represent graphs as pairs of string identifiers such as ("A", "B"). A standard technique is to assign each distinct name an integer index upon first encounter and then execute graph algorithms on the compact index representation. Assigning compact numeric identifiers to names in this way is called interning.

The graph maintains two structures: ids, which interns each name to a numeric index, and adj, the adjacency list indexed by those integers:

use std::collections::{HashMap, HashSet, VecDeque};

#[derive(Default)]
struct Graph {
    ids: HashMap<String, usize>,
    adj: Vec<Vec<usize>>,
}

Listing 12.6 The complete program. src/bin/graph_bfs.rs

use std::collections::{HashMap, HashSet, VecDeque};

#[derive(Default)]
struct Graph {
    ids: HashMap<String, usize>,
    adj: Vec<Vec<usize>>,
}

impl Graph {
    fn id(&mut self, name: &str) -> usize {
        *self
            .ids
            .entry(name.to_owned())
            .or_insert_with(|| {
                self.adj.push(vec![]);
                self.adj.len() - 1
            })
    }

    fn add_edge(&mut self, from: &str, to: &str) {
        let (u, v) = (self.id(from), self.id(to));
        self.adj[u].push(v);
    }

    fn bfs(&self, start: &str) -> Vec<usize> {
        let mut visited = HashSet::new();
        let mut queue = VecDeque::from([self.ids[start]]);
        let mut order = Vec::new();

        while let Some(node) = queue.pop_front() {
            if !visited.insert(node) {
                continue;
            }
            order.push(node);
            queue.extend(self.adj[node].iter());
        }
        order
    }
}

fn main() {
    let mut g = Graph::default();
    g.add_edge("A", "B");
    g.add_edge("A", "C");
    g.add_edge("B", "D");
    g.add_edge("C", "E");
    g.add_edge("D", "F");

    println!("{:?}", g.bfs("A")); // [0, 1, 2, 3, 4, 5]
}

Graph pairs two fields: ids, mapping each string label to its assigned integer index, and adj, an unweighted index-form adjacency list.

The id method performs interning in a single entry lookup. Calling self.ids.entry(name.to_owned()) queries the map, and or_insert_with invokes its closure exclusively when the label is absent, appending an empty adjacency vector to self.adj and returning its newly assigned index. Dereferencing with * copies out the usize identifier.

Although self.ids is mutably borrowed by the Entry handle while the closure mutates self.adj, Rust’s disjoint field borrow analysis permits both borrows simultaneously because they reference distinct struct fields.

This bfs implementation marks vertices upon dequeue rather than enqueue, matching the deferred-marking strategy of Section 12.4: a vertex may enter the queue multiple times, with subsequent copies skipped upon removal. Calling queue.extend(self.adj[node].iter()) enqueues all adjacent vertex indices in a single pass.

$ cargo run --bin graph_bfs
[0, 1, 2, 3, 4, 5]

The output reports interned integer indices rather than string labels; vertices A through F receive indices 0 through 5 in order of first insertion.

12.6 Finding cycles

Many systems must verify that a directed graph is acyclic: a build system cannot compile a target that depends on itself, and a curriculum planner cannot schedule circular prerequisites.

A single visited flag cannot reliably detect cycles. Consider the diamond on the right of Figure 12.4: DFS reaches D through B and later encounters D again through C, yet that second visit reflects converging paths rather than a cycle.

Cycle detection in directed graphs requires a three-state visitation state machine per vertex (standard white-gray-black DFS coloring):

  • Unvisited (white): DFS has not yet discovered the vertex.
  • Visiting (gray): The vertex is active on the current DFS recursion stack; its descendants are still being explored.
  • Done (black): All vertices reachable from this vertex have been completely explored and verified acyclic.

An edge targeting a Visiting vertex points to an ancestor on the active recursion stack and therefore closes a directed cycle; such an edge is classified as a back edge. An edge targeting a Done vertex enters a previously validated acyclic subgraph (a forward or cross edge) and cannot form a cycle.

12.6.1 A graph that owns its node data

Listing 12.7 The graph and its states (lines 1 to 30). src/bin/cyclic_graph.rs

use std::collections::VecDeque;

type NodeId = usize;

struct Graph<T> {
    nodes: Vec<T>,
    adj: Vec<Vec<NodeId>>, // adj[i] = nodes that i points to
}

#[derive(Clone, Copy)]
enum State {
    Unvisited,
    Visiting,
    Done,
}

impl<T> Graph<T> {
    fn new() -> Self {
        Self {
            nodes: Vec::new(),
            adj: Vec::new(),
        }
    }

    fn add_node(&mut self, data: T) -> NodeId {
        self.nodes.push(data);
        self.adj.push(Vec::new());
        self.nodes.len() - 1
    }

    fn add_edge(&mut self, from: NodeId, to: NodeId) {
        self.adj[from].push(to);
    }

    fn neighbors(&self, id: NodeId) -> impl Iterator<Item = NodeId> + '_ {
        self.adj[id].iter().copied()
    }
    // ...
}

This Graph<T> stores owned vertex payloads in a contiguous arena nodes: Vec<T> and represents edges as integer indices inside adj. Defining type NodeId = usize documents index semantics in method signatures; add_node allocates a slot and returns its NodeId handle for subsequent edge insertions.

Index-based arena storage is the idiomatic graph representation in Rust. Representing cyclic graphs with direct pointers or references requires reference counting (Rc) and interior mutability (RefCell), introducing runtime borrow checks and reference-cycle memory leaks; integer indices into a Vec eliminate ownership aliasing altogether while improving spatial cache locality.

The neighbors method returns impl Iterator<Item = NodeId> + '_, an opaque iterator type whose lifetime is tied to the borrow of self so that it cannot outlive the graph. Calling .copied() converts yielded &usize slice references into owned NodeId values.

These methods implement the BFS and DFS traversals of Sections 12.3 and 12.4 over the neighbors iterator. Filtering out already-visited neighbors via .filter(|&n| !visited[n]) before pushing reduces peak stack depth, but the post-pop visitation guard remains mandatory: two distinct ancestors may still enqueue the same unvisited vertex before either stack entry is popped.

Listing 12.9 Cycle detection (lines 76 to 94).

impl<T> Graph<T> {
    // ...
    fn has_cycle(&self) -> bool {
        let mut state = vec![State::Unvisited; self.nodes.len()];
        (0..self.nodes.len()).any(|n| self.visit(n, &mut state))
    }

    fn visit(&self, node: NodeId, state: &mut [State]) -> bool {
        match state[node] {
            State::Visiting => true, // back edge: cycle found
            State::Done => false,
            State::Unvisited => {
                state[node] = State::Visiting;
                let found = self.adj[node]
                    .iter()
                    .any(|&n| self.visit(n, state));
                state[node] = State::Done;
                found
            }
        }
    }
}

visit executes a recursive DFS that short-circuits and returns true upon encountering any back edge, dispatching on the vertex’s current state:

  • Visiting: the incoming edge is a back edge to an active ancestor, confirming a cycle (true).
  • Done: the subgraph rooted at this vertex has already been proven acyclic (false).
  • Unvisited: the vertex transitions to Visiting and recurses over its outgoing neighbors; .any(...) short-circuits as soon as any branch reports a cycle. Once all descendants return acyclic, the vertex transitions to Done.

Because a directed graph may contain disconnected components, has_cycle initiates visit from every vertex in 0..self.nodes.len(). All invocations share a single state vector, ensuring each vertex and edge is processed at most once for an overall time complexity of O(V + E).

12.6.2 The same graph with a HashMap

The second version stores the graph as a map from a node to its neighbors, with no numbering step.

The cycle check marks each node with a State: Visiting while its descendants are being explored, and Done after. The graph is a map from a node to its neighbors, generic over any Copy node type:

#[derive(Clone, Copy)]
enum State {
    Visiting,
    Done,
}

#[derive(Default)]
struct Graph<T> {
    adj: HashMap<T, Vec<T>>,
}

Listing 12.11 The complete program. src/bin/cyclic_graph_map.rs

use std::{
    collections::{HashMap, HashSet, VecDeque},
    hash::Hash,
};

#[derive(Clone, Copy)]
enum State {
    Visiting,
    Done,
}

#[derive(Default)]
struct Graph<T> {
    adj: HashMap<T, Vec<T>>,
}

impl<T: Copy + Eq + Hash> Graph<T> {
    fn add_edge(&mut self, u: T, v: T) {
        self.adj.entry(v).or_default();
        self.adj.entry(u).or_default().push(v);
    }

    fn bfs(&self, start: T) -> Vec<T> {
        let mut seen = HashSet::from([start]);
        let mut queue = VecDeque::from([start]);
        let mut order = vec![];

        while let Some(u) = queue.pop_front() {
            order.push(u);
            for &v in &self.adj[&u] {
                if seen.insert(v) {
                    queue.push_back(v);
                }
            }
        }
        order
    }

    fn has_cycle(&self) -> bool {
        fn dfs<T: Copy + Eq + Hash>(g: &Graph<T>, u: T, state: &mut HashMap<T, State>) -> bool {
            match state.get(&u) {
                Some(State::Visiting) => return true,
                Some(State::Done) => return false,
                None => {}
            }

            state.insert(u, State::Visiting);
            let found = g.adj[&u]
                .iter()
                .any(|&v| dfs(g, v, state));
            state.insert(u, State::Done);
            found
        }

        let mut state = HashMap::new();
        self.adj
            .keys()
            .any(|&u| dfs(self, u, &mut state))
    }
}

fn main() {
    let mut g = Graph::default();
    g.add_edge("A", "B");
    g.add_edge("B", "C");

12.7 A grid is a graph

A two-dimensional grid defines an implicit graph: each cell (r, c) represents a vertex, and its incident edges to orthogonally adjacent cells (up, down, left, right) are computed dynamically from coordinate offsets rather than materialized in an adjacency list.

The canonical connected-components problem on an implicit grid counts islands, where each island is a maximal 4-connected component of land cells (diagonal adjacency is excluded).

The algorithm scans the grid in row-major order. Whenever the scan encounters an unvisited land cell, it increments the component counter and executes a BFS flood fill from that seed cell to mark the entire connected component visited (Figure 12.5).

use std::collections::{HashSet, VecDeque};

fn count_islands<T: PartialEq>(grid: &[&[T]], land: T) -> usize {
    if grid.is_empty() || grid[0].is_empty() {
        return 0;
    }

    let rows = grid.len();
    let cols = grid[0].len();
    let mut visited = HashSet::new();
    let mut count = 0;
    let dirs = [(0, 1), (1, 0), (0, -1), (-1, 0)];

    // BFS closure: flood-fill one island starting from a known land cell.
    // Passing `visited` explicitly avoids borrow-checker friction when calling
    // the closure from the outer loop.
    let bfs = |start: (usize, usize), visited: &mut HashSet<(usize, usize)>| {
        let mut queue = VecDeque::new();
        queue.push_back(start);
        visited.insert(start);

        while let Some((cr, cc)) = queue.pop_front() {
            for &(dr, dc) in &dirs {
                let nr = cr as i32 + dr;
                let nc = cc as i32 + dc;

                if (0..rows as i32).contains(&nr) && (0..cols as i32).contains(&nc) {
                    let (ur, uc) = (nr as usize, nc as usize);
                    if grid[ur][uc] == land && !visited.contains(&(ur, uc)) {
                        visited.insert((ur, uc));
                        queue.push_back((ur, uc));
                    }
                }
            }
        }
    };

    for r in 0..rows {
        for c in 0..cols {
            if grid[r][c] == land && !visited.contains(&(r, c)) {
                count += 1;
                bfs((r, c), &mut visited);
            }
        }
    }

    count
}

The grid parameter has type &[&[T]] (a slice of row slices), parameterized over any T: PartialEq so callers may supply character, boolean, or integer matrices along with the sentinel value land: T.

dirs enumerates the four orthogonal (dr, dc) offsets. Because grid indices have unsigned type usize, subtracting 1 from coordinate 0 would underflow; the implementation widens coordinates to signed i32, validates bounds with (0..rows as i32).contains(&nr), and casts back to usize only after bounds verification succeeds.

The flood-fill routine is defined as a local closure bfs that borrows grid, dirs, rows, cols, and land immutably from its enclosing scope while receiving visited explicitly as a mutable parameter. Capturing visited mutably inside the closure would hold an exclusive borrow across the closure’s entire lifetime, preventing the outer scan loop from querying visited.contains; passing &mut visited per invocation restricts the mutable borrow to each flood-fill call.

Because each cell is examined a constant number of times, the algorithm runs in O(R × C) time for an R × C grid. Replacing the coordinate HashSet with a flat Vec<bool> of length R × C eliminates hashing overhead and improves spatial cache locality.

12.8 Putting tasks in order

When tasks have ordering constraints requiring certain prerequisites to complete before dependent tasks begin, a topological order arranges all tasks so that every dependency precedes its dependents. Build systems, package managers, and course planners rely on topological sorting.

Each directed edge points from a prerequisite to a task that depends on it. The indegree of a node is the number of incoming edges, representing the count of unresolved prerequisites.

Kahn’s algorithm constructs a topological order iteratively (Figure 12.6):

  1. Enqueue every vertex with indegree 0 (tasks with no unresolved prerequisites).
  2. Dequeue a vertex from the frontier and append it to the output topological ordering.
  3. For each outgoing edge from that vertex, decrement the target vertex’s indegree by 1; whenever a target’s indegree reaches 0, enqueue it.
  4. Repeat until the frontier queue is empty.

If the graph contains a directed cycle, every vertex participating in or depending on that cycle retains an indegree of at least 1 and never enters the frontier. Consequently, the resulting sequence contains strictly fewer than |V| vertices, providing a complete O(V + E) cycle-detection condition.

pub fn topological_sort(num_nodes: usize, edges: &[(usize, usize)]) -> Option<Vec<usize>> {
    // ...
    while let Some(node) = queue.pop_front() {
        order.push(node);

        for &next in &graph[node] {
            indegree[next] -= 1;
            if indegree[next] == 0 {
                queue.push_back(next);
            }
        }
    }

    (order.len() == num_nodes).then_some(order)
}

Each dequeued vertex is appended to order. Logically removing it from the graph decrements the indegree of each adjacent dependent vertex; any dependent whose indegree reaches 0 has all prerequisites satisfied and enters the frontier.

The final expression (order.len() == num_nodes).then_some(order) yields Some(order) when every vertex was scheduled and None when a directed cycle prevented one or more vertices from reaching indegree 0.

fn topo_sort(courses: &[Course]) -> Vec<String> {
    let mut adj: HashMap<String, Vec<String>> = HashMap::new();
    let mut indegree: HashMap<String, usize> = HashMap::new();

    for Course { name, depends_on } in courses {
        indegree.insert(name.clone(), depends_on.len());
        adj.entry(name.clone()).or_default();
        for dep in depends_on {
            adj.entry(dep.clone())
                .or_default()
                .push(name.clone());
            indegree.entry(dep.clone()).or_insert(0);
        }
    }

    let mut queue: VecDeque<_> = indegree
        .iter()
        .filter(|&(_, deg)| *deg == 0)
        .map(|(name, _)| name.clone())
        .collect();

        for next in &adj[&node] {
            let d = indegree.get_mut(next).unwrap();
            *d -= 1;
            if *d == 0 {
                queue.push_back(next.clone());
            }
        }
        order.push(node);
    }

    if order.len() == indegree.len() {
        order
    } else {
        Vec::new()
    }
}

12.9 Shortest paths

In a weighted graph, the cost of a path is the sum of its constituent edge weights, and a shortest path between two vertices minimizes that total weight rather than edge cardinality.

Whereas unweighted BFS minimizes hop count, Dijkstra’s algorithm computes single-source shortest paths from a start vertex to all reachable vertices in any graph with non-negative edge weights.

12.9.1 How Dijkstra’s algorithm works

Dijkstra’s algorithm maintains two auxiliary structures:

  • dist, storing the best known upper-bound path cost from the source to each vertex (initialized to 0 for the source).
  • A min-priority queue of (cost, vertex) entries, implemented with BinaryHeap and Reverse, so that the minimum-cost unsettled frontier vertex is always extracted next.

On each iteration, the algorithm extracts the minimum-cost entry (d, u) from the heap. For every outgoing edge (u, v, w), it evaluates the candidate path cost d + w; if this candidate strictly improves upon dist[v], the algorithm updates dist[v] and pushes (d + w, v) onto the heap. Tightening a vertex’s distance upper bound in this manner is called an edge relaxation step.

When a vertex u is extracted with its current recorded cost d == dist[u], its shortest-path distance is permanently settled. Because all remaining heap entries have cost at least d and edge weights are non-negative, no future path can reach u with a strictly lower total cost.

Because std::collections::BinaryHeap does not support an in-place decrease-key operation, relaxing an edge to a vertex already in the heap pushes a second, lower-cost entry while leaving the earlier entry intact. When that superseded entry is eventually popped, its cost exceeds dist[u] and the algorithm discards it; such entries are termed stale (lazy deletion).

Tracing the table in Figure 12.7 row by row illustrates how stale entries arise. Settling A records B at cost 4 and C at cost 1. Settling C discovers a cheaper path to B at cost 1 + 2 = 3, which replaces 4 and pushes a new heap entry while leaving (4, B) stale. Settling B at cost 3 then relaxes D from 6 down to 4. use std::{
    cmp::Reverse,
    collections::{BinaryHeap, HashMap},
    hash::Hash,
};

use crate::problems::graph_bfs::GraphAdjList;

/// Shortest distances from `start_node` over an index-based adjacency list.
pub fn dijkstra_vec(graph: &[Vec<(usize, u32)>], start_node: usize) -> Vec<Option<u32>> {
    let mut distances = vec![None; graph.len()];
    let mut min_heap = BinaryHeap::from([Reverse((0, start_node))]);

    distances[start_node] = Some(0);

    while let Some(Reverse((current_cost, current_node))) = min_heap.pop() {
        // stale heap entry, a shorter path was already recorded
        if distances[current_node].is_some_and(|best| current_cost > best) {
            continue;
        }
        for &(neighbor, weight) in &graph[current_node] {
            let new_distance = current_cost + weight;
            if distances[neighbor].is_none_or(|best| new_distance < best) {
                distances[neighbor] = Some(new_distance);
                min_heap.push(Reverse((new_distance, neighbor)));
            }
        }
    }
    distances
}

Distance upper bounds are stored in Vec<Option<u32>>, where None represents infinity (no path discovered yet). Two Option combinators express the core invariants cleanly:

  • is_some_and(|best| current_cost > best) identifies stale heap entries whose popped cost exceeds the settled or improved distance in distances.
  • is_none_or(|best| new_distance < best) evaluates the relaxation predicate, returning true when the neighbor is unreached or when the candidate path strictly lowers its recorded distance.

The heap stores Reverse((cost, node)). Because BinaryHeap is a max-heap by default, wrapping tuples in Reverse inverts the ordering into a min-heap; Rust orders tuples lexicographically, prioritizing cost first and breaking ties deterministically by vertex index.

Listing 12.17 Dijkstra over the map form (lines 46 to 73).

/// Shortest distances from `start_node` over a `HashMap` adjacency list.
pub fn dijkstra<Node>(graph: &GraphAdjList<Node>, start_node: Node) -> HashMap<Node, u32>
where
    Node: Copy + Eq + Hash + Ord,
{
    let mut distances = HashMap::from([(start_node, 0)]);
    let mut min_heap = BinaryHeap::from([Reverse((0, start_node))]);

    while let Some(Reverse((current_cost, current_node))) = min_heap.pop() {
        // stale heap entry, a shorter path was already recorded
        if current_cost > distances[&current_node] {
            continue;
        }
        for &(neighbor, weight) in graph[&current_node] {
            let new_distance = current_cost + weight;

            if new_distance
                < *distances
                    .get(&neighbor)
                    .unwrap_or(&u32::MAX)
            {
                distances.insert(neighbor, new_distance);
                min_heap.push(Reverse((new_distance, neighbor)));
            }
        }
    }
    distances
}

In this map-backed formulation, distances is a HashMap populated lazily with reached vertices, and Node requires an Ord bound to support lexicographic tie-breaking inside the priority queue.

Indexing distances[&current_node] is guaranteed not to panic because every vertex is inserted into distances prior to being pushed onto the heap. Calling distances.get(&neighbor).unwrap_or(&u32::MAX) treats unreached vertices as having cost u32::MAX (infinity).

Because each edge relaxation pushes at most one entry onto a heap of size O(E) and each heap push or pop takes O(log E) time, the total time complexity is O((V + E) log E), which simplifies to O(E log V) for connected simple graphs.

    Node: Clone + Hash + Ord,

    Node: Hash + Ord,

                continue;

Both Edge<Node> and AdjMap<Node> are generic over the vertex identifier type Node (such as &str, String, or u32).

To eliminate key cloning, this implementation stores borrowed references &'a Node inside dist and the priority queue, removing the Clone trait bound entirely and avoiding heap allocations when vertices are owned String values.

The explicit lifetime parameter 'a binds the input graph, the start vertex reference, and the keys of the returned distance map to a common borrow scope. Because every &edge.to reference pushed onto the heap borrows directly from graph, the borrow checker enforces statically that graph remains immutable and valid for as long as the returned distance map is accessed.

Two let ... else guards harden this implementation against runtime panics:

  • let Some(edges) = graph.get(node) else { continue }; tolerates sink vertices omitted from the adjacency map (such as "D" in main).
  • let Some(new_cost) = cost.checked_add(edge.weight) else { continue }; skips edges whose cumulative path cost would overflow u64::MAX, preventing both debug panics and release-mode wraparound.

12.10 Connecting every node at the lowest cost

The final graph problem operates on an undirected, weighted graph. Modeling buildings as nodes and cabling costs as edge weights, the objective is to connect every node directly or indirectly at the minimum total edge weight.

A subset of edges connecting all vertices of an undirected graph without cycles is a spanning tree; a spanning tree of minimum total edge weight is a minimum spanning tree (MST). Every spanning tree over |V| = n vertices contains exactly n − 1 edges: removing any edge disconnects the graph, and adding any edge introduces a cycle.

Kruskal’s algorithm constructs an MST greedily by examining edges in non-decreasing order of weight. An edge is accepted into the spanning forest if and only if its endpoints belong to distinct connected components; any edge whose endpoints are already connected is discarded because it would close a cycle.

12.10.1 Union-find

Kruskal’s algorithm requires dynamic connectivity queries and component merges. A disjoint-set union (DSU or union-find) data structure maintains a partition of vertices into disjoint sets with near-constant amortized cost.

Each connected component is represented as an inverted tree encoded in a flat parent array, where parent[i] stores the parent index of vertex i. A component’s canonical representative (its root) satisfies parent[r] == r; two vertices belong to the same connected component if and only if they share the same root.

The structure exposes two core operations:

  • find(x) traverses parent pointers from x to its component root.
  • union(x, y) resolves the roots of x and y; if they differ, it links one root under the other to merge the two components.

Listing 12.22 Union-find (lines 10 to 49). src/bin/kruskals_algorithm.rs

use std::cmp::Ordering::{Equal, Greater, Less};

struct DisjointSet {
    parent: Vec<usize>,
    rank: Vec<usize>,
}

impl DisjointSet {
    fn new(n: usize) -> Self {
        Self {
            parent: (0..n).collect(),
            rank: vec![0; n],
        }
    }

    fn find(&mut self, elem: usize) -> usize {
        if self.parent[elem] != elem {
            self.parent[elem] = self.find(self.parent[elem]);
        }

        self.parent[elem]
    }

    fn union(&mut self, x: usize, y: usize) -> bool {
        let (x, y) = (self.find(x), self.find(y));

        if x == y {
            return false;
        }

        match self.rank[x].cmp(&self.rank[y]) {
            Less => self.parent[x] = y,
            Greater => self.parent[y] = x,
            Equal => {
                self.parent[x] = y;
                self.rank[y] += 1;
            }
        }

        true
    }
}

new initializes n singleton components by setting parent to [0, 1, ..., n - 1] via (0..n).collect().

find resolves the root recursively and rewrites parent[elem] directly to the root on stack unwind, flattening the lookup path so subsequent queries resolve in a single hop. This optimization is path compression.

union returns false if both vertices already share a root. Otherwise it merges the two trees via union by rank, attaching the tree of smaller rank beneath the root of higher rank to keep tree height logarithmic; when both roots share equal rank, one becomes the parent and its rank increments by 1.

Combined, path compression and union by rank achieve an amortized time complexity of O(α(V)) per operation, where α is the inverse Ackermann function (effectively constant for all practical graph sizes).

fn kruskals(n: usize, mut edges: Vec<Edge>) -> Vec<Edge> {
    // Kruskal's algorithm is greedy: it takes the cheapest edges first.
    edges.sort_by_key(|e| e.w);

    let mut uf = DisjointSet::new(n);
    let mut mst = Vec::new();

        if uf.union(edge.u, edge.v) {

        }
    }

    mst
}

An Edge connects zero-indexed vertices u and v with weight w; because the graph is undirected, endpoint order is symmetric.

edges.sort_by_key(|e| e.w) orders all edges by non-decreasing weight. Each edge is then tested via uf.union(edge.u, edge.v): a true return value indicates that the endpoints belonged to disjoint components, so the edge is moved directly into mst without copying (for edge in edges consumes the vector by value).

Edge sorting dominates the asymptotic complexity, yielding O(E log E) total time.

//! Breadth-first search.
//!
//! Two variants of the same algorithm:
//!
//! - `bfs_vec`: nodes are `usize` indices and the graph is `Vec<Vec<(usize, u32)>>`,
//!   so `visited` is a plain `Vec<bool>`. This is the version to write first.
//! - `bfs`: nodes are any `Copy + Eq + Hash` type and the graph is a `HashMap`
//!   from a node to a slice of `(neighbor, weight)` edges.

use std::{
    collections::{HashMap, HashSet, VecDeque},
    hash::Hash,
};

/// Adjacency list keyed by node: each node maps to its `(neighbor, weight)` edges.
pub type GraphAdjList<'a, Node> = HashMap<Node, &'a [(Node, u32)]>;

/// BFS over an index-based adjacency list. Returns nodes in visiting order.
pub fn bfs_vec(graph: &[Vec<(usize, u32)>], start_node: usize) -> Vec<usize> {
    let mut visited = vec![false; graph.len()];
    let mut queue = VecDeque::from([start_node]);
    let mut result = vec![];

    visited[start_node] = true;

    while let Some(current_node) = queue.pop_front() {
        result.push(current_node);
        for &(neighbor, _) in &graph[current_node] {
            if !visited[neighbor] {
                visited[neighbor] = true;
                queue.push_back(neighbor);
            }
        }
    }
    result
}

/// BFS over a `HashMap` adjacency list. Returns nodes in visiting order.
pub fn bfs<Node>(graph: &GraphAdjList<Node>, start_node: Node) -> Vec<Node>
where
    Node: Copy + Eq + Hash,
{
    let mut visited = HashSet::new();
    let mut queue = VecDeque::from([start_node]);
    let mut result = vec![];

    visited.insert(start_node);

    while let Some(current_node) = queue.pop_front() {
        result.push(current_node);
        // slice iter yields &(Node, u32); `&` destructures it
        for &(neighbor, _) in graph[&current_node] {
            if visited.insert(neighbor) {
                queue.push_back(neighbor);
            }
        }
    }
    result
}

//! Dijkstra's shortest paths with a binary min-heap.
//!
//! Two variants of the same algorithm:
//!
//! - `dijkstra_vec`: nodes are `usize` indices and distances are a
//!   `Vec<Option<u32>>`, where `None` means unreachable.
//! - `dijkstra`: nodes are any `Copy + Eq + Hash + Ord` type and distances are a
//!   `HashMap` containing only the reachable nodes.
//!
//! Edge weights must be non-negative, which `u32` guarantees. `BinaryHeap` is a
//! max-heap, so entries are wrapped in `Reverse` to pop the smallest cost first.
//! A node can be in the heap several times; an entry whose cost is larger than the
//! recorded distance is stale and skipped.

use std::{
    cmp::Reverse,
    collections::{BinaryHeap, HashMap},
    hash::Hash,
};

use crate::problems::graph_bfs::GraphAdjList;

/// Shortest distances from `start_node` over an index-based adjacency list.
pub fn dijkstra_vec(graph: &[Vec<(usize, u32)>], start_node: usize) -> Vec<Option<u32>> {
    let mut distances = vec![None; graph.len()];
    let mut min_heap = BinaryHeap::from([Reverse((0, start_node))]);

    distances[start_node] = Some(0);

    while let Some(Reverse((current_cost, current_node))) = min_heap.pop() {
        // stale heap entry, a shorter path was already recorded
        if distances[current_node].is_some_and(|best| current_cost > best) {
            continue;
        }
        for &(neighbor, weight) in &graph[current_node] {
            let new_distance = current_cost + weight;
            if distances[neighbor].is_none_or(|best| new_distance < best) {
                distances[neighbor] = Some(new_distance);
                min_heap.push(Reverse((new_distance, neighbor)));
            }
        }
    }
    distances
}

/// Shortest distances from `start_node` over a `HashMap` adjacency list.
pub fn dijkstra<Node>(graph: &GraphAdjList<Node>, start_node: Node) -> HashMap<Node, u32>
where
    Node: Copy + Eq + Hash + Ord,
{
    let mut distances = HashMap::from([(start_node, 0)]);
    let mut min_heap = BinaryHeap::from([Reverse((0, start_node))]);

    while let Some(Reverse((current_cost, current_node))) = min_heap.pop() {
        // stale heap entry, a shorter path was already recorded
        if current_cost > distances[&current_node] {
            continue;
        }
        for &(neighbor, weight) in graph[&current_node] {
            let new_distance = current_cost + weight;

            if new_distance
                < *distances
                    .get(&neighbor)
                    .unwrap_or(&u32::MAX)
            {
                distances.insert(neighbor, new_distance);
                min_heap.push(Reverse((new_distance, neighbor)));
            }
        }
    }
    distances
}

Summary

  • A graph G = (V, E) permits arbitrary vertex connectivity and cycles, requiring every traversal to maintain an explicit visitation state structure.
  • Adjacency lists represent sparse graphs cleanly: the dense index form (Vec<Vec<...>>) maximizes cache locality and throughput, whereas the map form (HashMap) accommodates arbitrary hashable vertex identifiers.
  • BFS uses a FIFO queue to explore vertices in non-decreasing hop distance, whereas DFS uses a LIFO stack to explore full branches before backtracking; both run in O(V + E) time.
  • Arena-style integer indexing (NodeId = usize) eliminates reference-cycle ownership hazards in Rust graphs.
  • Directed cycle detection requires a three-state visitation machine (Unvisited, Visiting, Done); an edge targeting a Visiting ancestor is a back edge that closes a cycle.
  • Two-dimensional grids form implicit graphs whose orthogonal edges are computed from coordinate offsets, enabling O(R × C) flood-fill connected-component counting.
  • Kahn’s algorithm computes a topological ordering in O(V + E) time by iteratively removing zero-indegree vertices; producing fewer than |V| vertices proves the presence of a directed cycle.
  • Dijkstra’s algorithm computes single-source shortest paths over non-negative edge weights in O(E log V) time using a min-heap with lazy stale-entry deletion, hardened by checked_add and let ... else guards.
  • Kruskal’s algorithm constructs a minimum spanning tree in O(E log E) time by sorting edges and querying disjoint-set union with path compression and union by rank.
