Linked lists

This chapter covers

  • What a linked list is, and how it differs from a Vec in memory
  • Moving ownership of nodes with Option::take and std::mem::replace
  • Reversing a list in place
  • Four ways to write a list node, measured against each other
  • Why dropping a long list can crash the program, and how to prevent it
  • A doubly linked list built from Rc, RefCell, and Weak

A linked list is a linear, pointer-linked dynamic data structure in which each node is independently allocated and stores an explicit link to its successor (and, in a doubly linked list, its predecessor). Unlike contiguous arrays, linked lists support O(1) structural splicing and head mutation without shifting elements, at the cost of pointer chasing and per-node allocation overhead. In Rust, implementing linked lists tests ownership transfer and aliasing invariants directly because every structural edit moves node ownership from one link to another under compile-time borrow verification.

The implementations in this chapter progress from singly linked lists with in-place reversal and cursor-based deletion, to an empirical comparison of four node layouts under a unified benchmark harness, to diagnosing and eliminating recursive Drop stack overflows, and finally to a doubly linked list constructed from Rc, RefCell, and Weak.

9.1 What a linked list is

A linked list stores an ordered sequence across discrete heap-allocated nodes, each pairing a payload with an optional pointer to its successor. The list header stores a single pointer to the initial node (the head), and a None link terminates the chain.

Figure 9.1 contrasts a singly linked list with a contiguous Vec storing the same three values.

The two structures exhibit complementary asymptotic and memory-layout trade-offs:

OperationVecSingly linked list
Read the value at position iO(1): compute the addressO(i): follow i pointers
Add or remove at the frontO(n): shift every elementO(1): change the head pointer
Add at the endamortized O(1)O(n), unless the list keeps a tail pointer
Memory per valuethe valuethe value, a pointer, and a heap block’s overhead

Conceptually, a linked list resembles a chain of pointers where each node reveals only the location of its successor: reaching the fifth node requires traversing the first four, whereas inserting a new head updates a single pointer without moving existing nodes. By contrast, a Vec stores elements contiguously like a numbered row of slots: indexing position 5 is a single address calculation, whereas inserting at the front shifts every existing element.

In practice, contiguous storage (Vec) outperforms pointer-linked lists across most workloads due to superior spatial cache locality and hardware prefetching. Nevertheless, the ownership-transfer idioms developed here (atomic replacement, cursor traversal, and iterative Drop) recur throughout recursive trees and graphs.

In Rust, each node owns its successor through a Box, and None terminates the chain, giving the next field the type Option<Box<Node>>.

9.2 Moving nodes: take and replace

Every list manipulation transfers a node from one owner to another. Rust’s memory safety rules prohibit moving a value directly out of a borrowed location, because doing so would leave the location uninitialized for its owner.

Two standard library operations resolve this by atomically substituting a valid replacement as the old value is extracted:

  • option.take() moves the value out of an Option and leaves None in its place.
  • std::mem::replace(&mut place, new_value) moves the old value out and writes new_value into its place.

Figure 9.2 illustrates take operating on a node’s next field.

These two operations appear throughout the listings in this chapter.

9.3 Reversing a list

The problem. Given a singly linked list 1 → 2 → 3 → 4, reverse it in place to 4 → 3 → 2 → 1 by rewiring pointers without copying node values.

The idea. Traverse the list from front to back using two bindings: previous holds the already-reversed prefix, and current holds the remaining unvisited suffix. Each iteration detaches the head of current, points its next link at previous, and advances previous to that node (Figure 9.3).

Listing 9.1 defines the node struct along with two conversion helpers for constructing and inspecting lists.

Listing 9.1 The node and two helpers (lines 1 to 33). src/problems/linked_list.rs

//! Reverse a singly linked list, and remove nodes from it.
//!
//! Uses `Option<Box<ListNode>>` and a `while let` loop to move pointers in a
//! borrow-safe way. Removal walks a cursor: a mutable borrow of one link.

#[derive(Debug, PartialEq, Eq)]
pub struct ListNode {
    pub val: i32,
    pub next: Option<Box<ListNode>>,
}

impl ListNode {
    pub fn from_slice(values: &[i32]) -> Option<Box<ListNode>> {
        let mut head = None;
        for &value in values.iter().rev() {
            head = Some(Box::new(ListNode {
                val: value,
                next: head,
            }));
        }
        head
    }

    pub fn to_vec(head: Option<Box<ListNode>>) -> Vec<i32> {
        let mut result = Vec::new();
        let mut current = head;
        while let Some(node) = current {
            result.push(node.val);
            current = node.next;
        }
        result
    }
}

The from_slice helper iterates over the input slice in reverse, prepending each element to the front of the list so values[0] ends up at the head without maintaining a tail pointer. Conversely, to_vec consumes the list by value: each iteration of while let Some(node) = current moves one Box out of current and transfers node.next back to current before the node is freed.

Animation 9.2 traces from_slice and to_vec on [1, 2, 3] and illustrates how omitting .rev() inverts the resulting order.

Listing 9.2 implements the in-place reversal.

Listing 9.2 Reversing the list (lines 35 to 46).

pub fn reverse_list(head: Option<Box<ListNode>>) -> Option<Box<ListNode>> {
    let mut previous = None;
    let mut current = head;

    while let Some(mut node) = current {
        current = node.next.take();
        node.next = previous;
        previous = Some(node);
    }

    previous
}

Each iteration executes three ownership transfers:

  1. current = node.next.take(); detaches the remaining suffix from node (Figure 9.2).
  2. node.next = previous; reverses the node’s successor pointer toward the reversed prefix.
  3. previous = Some(node); advances the reversed head to node.

Tracing the invariant across 1 → 2 → 3:

After passpreviouscurrent
startNone1 → 2 → 3
112 → 3
22 → 13
33 → 2 → 1None

At no point do two bindings own the same node, which satisfies the borrow checker. The traversal visits each node once in O(n) time and O(1) auxiliary space.

9.4 Removing nodes with a cursor

The problem. Remove every node whose value equals target in a single pass, including matches at the head or consecutive matches.

The idea. Unlinking a node requires mutating the link that owns it, which is either head or the preceding node’s next field. Rather than tracking a node directly, the loop maintains a mutable reference to the owning link itself: a &mut Option<Box<ListNode>> called a cursor.

The cursor acts as a pointer to a single link in the chain. When the link points to a matching node, the link is redirected past that node and the cursor remains in place to inspect the newly promoted successor. When the node does not match, the cursor advances to that node’s next link.

Listing 9.3 Removing every match (lines 48 to 71). src/problems/linked_list.rs

/// Remove every node whose value is `target`, in one pass.
///
/// `cursor` is a mutable borrow of a link: first `head`, then the `next` of
/// each node that stays. A matching node is unlinked by moving its `next` into
/// the link that pointed at it. The cursor does not move after a removal,
/// because the link it holds now points at a node not yet checked.
pub fn remove_all(mut head: Option<Box<ListNode>>, target: i32) -> Option<Box<ListNode>> {
    let mut cursor = &mut head;
    while cursor.is_some() {
        let node = cursor
            .as_mut()
            .expect("checked by is_some");
        if node.val == target {
            let next = node.next.take();
            *cursor = next;
        } else {
            cursor = &mut cursor
                .as_mut()
                .expect("checked by is_some")
                .next;
        }
    }
    head
}

The loop proceeds in four steps:

  1. let mut cursor = &mut head; anchors the cursor on the head link. Treating head identically to any next field eliminates special-case code for removing the first node.
  2. cursor.as_mut() mutably borrows the node referenced by the current link.
  3. On a match, node.next.take() detaches the remainder of the list and *cursor = next rebinds the link to it, dropping the unlinked node immediately.
  4. Otherwise, cursor = &mut cursor...next advances the cursor to the current node’s next link.

Keeping the cursor stationary after a removal ensures that consecutive matches are never skipped, because the link now points to an uninspected node. Tracing 2 → 1 → 2 → 2 → 3 with target = 2 yields:

StepThe cursor holdsThe node thereAction
1head2match: head now points at 1
2head1keep: the cursor moves to 1’s next
31’s next2match: 1’s next now points at the second 2
41’s next2match: 1’s next now points at 3
51’s next3keep: the cursor moves to 3’s next
63’s nextNonethe loop ends: 1 → 3

Each node is inspected once in O(n) time and O(1) auxiliary space. Animation 9.3 traces this example alongside three edge cases: an absent target, a list where every node matches, and the bug introduced by advancing the cursor unconditionally after a removal.

The unit tests exercise the boundary conditions that commonly invalidate pointer-unlinking logic: matching at the head, consecutive duplicate matches, an absent target, an all-matching list, and an empty list.

9.5 A list written as an enum

The preceding formulation separated ListNode from the Option sentinel. An algebraic alternative unifies both into a single recursive enum whose variants represent either the empty list or a node owning a payload and its tail.

Listing 9.4 The list type (lines 1 to 13). src/bin/singly_linked_list.rs

// Singly linked list using an algebraic data type.
//
//    List<T> = Empty
//            | Node { value: T, next: Link<T> }
//
// `Empty` is the end of the list.

type Link<T> = Box<List<T>>;

pub enum List<T> {
    Empty,
    Node { value: T, next: Link<T> },
}

List<T> is parameterized over an arbitrary element type T, and type Link<T> = Box<List<T>> aliases the heap-indirected recursive tail.

Listing 9.5 Creating, checking, and measuring (lines 16 to 29).

impl<T> List<T> {
    pub fn new() -> Self {
        List::Empty
    }

    pub fn is_empty(&self) -> bool {
        matches!(self, List::Empty)
    }

    pub fn len(&self) -> usize {
        match self {
            List::Empty => 0,
            List::Node { next, .. } => 1 + next.len(),
        }
    }
    // ...
}

The len method counts nodes recursively, returning 0 for Empty and adding 1 to the length of the tail for Node. Because each recursive call waits on the next, an n-node list consumes n stack frames, a limitation examined in Section 9.7.

Listing 9.6 Adding and removing at the front (lines 31 to 49).

impl<T> List<T> {
    // ...
    /// O(1)
    pub fn push_front(&mut self, value: T) {
        let old = std::mem::replace(self, List::Empty);
        *self = List::Node {
            value,
            next: Link::new(old),
        };
    }

    /// O(1)
    pub fn pop_front(&mut self) -> Option<T> {
        match std::mem::replace(self, List::Empty) {
            List::Empty => None,
            List::Node { value, next } => {
                *self = *next;
                Some(value)
            }
        }
    }
}

Both push_front and pop_front take &mut self to mutate the list in place, relying on std::mem::replace from Section 9.2. Moving the existing list directly out of *self would leave *self temporarily uninitialized; replace(self, List::Empty) atomically installs a temporary Empty variant while returning ownership of the previous list.

In push_front, the old list is wrapped inside a new Node and written back into *self. In pop_front, matching on the old list returns None for Empty (leaving *self empty) or unboxes the tail with *self = *next for Node before returning the front value.

Animation 9.4 traces both operations and contrasts them with the direct move that the compiler rejects.

9.6 Four node layouts, measured

Sections 9.3 and 9.5 introduced two distinct node representations: a struct linked through Option<Box<Node>> and a recursive enum. To compare their throughput and deallocation behavior empirically, the benchmark below unifies four list variants behind a single trait interface so one generic driver exercises all four identically.

9.6.1 One trait for four lists

Sharing a single trait interface allows the benchmark harness to execute identical workloads against all four implementations via static dispatch.

Listing 9.7 The trait every list implements. benchmarking_examples/lists/mod.rs

//! Singly linked lists in four variants, so one benchmark loop can cover all of
//! them.
//!
//! The variants differ only in how a node is stored and in how the list frees
//! itself. `boxed` and `enum_node` free a chain of boxes recursively, which
//! overflows the stack past roughly 265,000 nodes. `boxed_drop` and `enum_drop`
//! unlink iteratively and scale.

pub mod boxed;
pub mod boxed_drop;
pub mod enum_drop;
pub mod enum_node;

/// The operations every variant supports, so the benchmark can be written once.
pub trait SinglyList<T>: Sized {
    /// A new, empty list.
    fn new() -> Self;

    /// Adds `value` to the front of the list.
    fn push_front(&mut self, value: T);

    /// Removes and returns the front value, if there is one.
    fn pop_front(&mut self) -> Option<T>;

    /// Whether the list holds nothing.
    fn is_empty(&self) -> bool;

    /// The variant's name, for benchmark output and error messages.
    fn variant() -> &'static str;
}

SinglyList<T>: Sized defines the minimal stack interface (new, push_front, pop_front, is_empty, and a diagnostic variant label) and constrains implementors to statically sized types for monomorphized generic dispatch. The four pub mod declarations expose each layout implementation from its own submodule.

The first two implementations realize the boxed-struct and recursive-enum layouts:

Listing 9.8 Option<Box<Node<T>>>: the types, push_front, and pop_front (lines 9 to 38). benchmarking_examples/lists/boxed.rs

struct Node<T> {
    value: T,
    next: Option<Box<Node<T>>>,
}

pub struct LinkedList<T> {
    head: Option<Box<Node<T>>>,
}

impl<T> SinglyList<T> for LinkedList<T> {
    fn new() -> Self {
        Self { head: None }
    }

    fn push_front(&mut self, value: T) {
        self.head = Some(Box::new(Node {
            value,
            // .take() leaves None in its place and extracts the old head
            next: self.head.take(),
        }));
    }

    fn pop_front(&mut self) -> Option<T> {
        self.head.take().map(|node| {
            // Point the list head to the next node in line
            self.head = node.next;
            // Return the unboxed value
            node.value
        })
    }
    // ...
}

Listing 9.9 enum ListNode<T>: the types, push_front, and pop_front (lines 9 to 44). benchmarking_examples/lists/enum_node.rs

enum ListNode<T> {
    Empty,
    Next(T, Box<ListNode<T>>),
}

pub struct LinkedList<T> {
    head: ListNode<T>,
}

impl<T> SinglyList<T> for LinkedList<T> {
    fn new() -> Self {
        Self {
            head: ListNode::Empty,
        }
    }

    fn push_front(&mut self, value: T) {
        // Extract the old head and leave Empty in its place
        let old_head = std::mem::replace(&mut self.head, ListNode::Empty);

        // Wrap the old head inside a Box behind the new value
        self.head = ListNode::Next(value, Box::new(old_head));
    }

    fn pop_front(&mut self) -> Option<T> {
        let old_head = std::mem::replace(&mut self.head, ListNode::Empty);

        match old_head {
            ListNode::Empty => None,
            ListNode::Next(value, next_node) => {
                // Point the list head to the next node in the sequence
                self.head = *next_node;
                Some(value)
            }
        }
    }
    // ...
}

Each file also has is_empty and variant, which are one line each. The two files implement the trait with impl<T> SinglyList<T> for LinkedList<T>. Each uses the tool from section 9.2 that fits its type: take() on the Option in the struct version, and mem::replace on the enum.

9.6.2 What each node costs in memory

Figure 9.4 draws both lists after pushing 10, 20, and 30.

On a 64-bit target with u64 payloads, both representations occupy 16 bytes per node (8 bytes for the payload and 8 bytes for the pointer). Because Box carries a non-null niche invariant, the compiler applies null-pointer optimization to both Option<Box<Node<T>>> and enum ListNode<T>, encoding None and Empty as the null address without an extra discriminant word.

Despite identical node sizes, the two layouts differ structurally in two respects. First, the enum representation stores its head node (16 bytes) inline within the list header, so each push_front copies 16 bytes into a newly allocated Box, whereas the boxed-struct layout moves only an 8-byte pointer. Second, the enum chain terminates with a heap-allocated Empty sentinel box. Both designs perform one heap allocation per push, yet the enum layout transfers twice as many inline bytes per operation.

Animation 9.5 pushes 10, 20, and 30 onto both lists, pops one value, and then pops from two empty lists.

9.7 When dropping a list crashes

Consider the following snippet using the struct-based list:

let mut list = boxed::LinkedList::new();
for value in 0..270_000u64 {
    list.push_front(value);
}
// list goes out of scope here and is dropped

Construction succeeds, but execution terminates at the closing brace when list is dropped:

thread 'main' has overflowed its stack
fatal runtime error: stack overflow, aborting

None of the list’s methods are recursive; the recursion resides in the compiler-generated drop glue. Dropping the list drops head, which drops the first Box<Node>, which recursively drops its next field, nesting one call frame per node (Figure 9.5, left).

Animation 9.6 compares the default recursive drop against an iterative implementation, illustrating the stack depth for each.

On most systems, the main thread receives an 8 MiB stack. Because the overflow occurs between 260,000 and 270,000 nodes, each nested drop frame consumes roughly 32 bytes. Threads spawned via std::thread::spawn default to a 2 MiB stack and therefore overflow at roughly one quarter of that length.

Eliminating this recursion requires a custom iterative Drop implementation. Rust invokes Drop::drop automatically before dropping a value’s fields.

Listing 9.10 The struct version's Drop (lines 46 to 55). benchmarking_examples/lists/boxed_drop.rs

impl<T> Drop for LinkedList<T> {
    fn drop(&mut self) {
        // Walk the chain and unlink each node before it is freed, so no node's
        // drop has to carry the rest of the list on the stack.
        let mut current = self.head.take();
        while let Some(mut node) = current {
            current = node.next.take();
        }
    }
}

The module boxed_drop.rs retains the layout and methods of Listing 9.8, adding only this iterative Drop implementation:

  1. let mut current = self.head.take(); transfers ownership of the entire chain out of self.
  2. while let Some(mut node) = current moves the leading Box<Node<T>> into a loop-local binding.
  3. current = node.next.take(); detaches the remainder of the chain before node is dropped.
  4. At the end of each iteration, node is deallocated with node.next == None, preventing recursive drop descent.

Consequently, deallocation executes in O(1) auxiliary stack space regardless of list cardinality.

Listing 9.11 The enum version's Drop (lines 52 to 62). benchmarking_examples/lists/enum_drop.rs

impl<T> Drop for LinkedList<T> {
    fn drop(&mut self) {
        // Take the chain out of the list first, then step it forward one node at
        // a time. Each node has already lost its `next` by the time it is freed,
        // so the drop stays on the heap.
        let mut current = std::mem::replace(&mut self.head, ListNode::Empty);
        while let ListNode::Next(_, next) = current {
            current = *next;
        }
    }
}

The enum version does the same with mem::replace and a while let ListNode::Next(_, next) = current loop. current = *next; moves the rest of the chain out of the box. Assigning to current drops its old value, a Next whose box has already been emptied, so again nothing nests.

9.8 The benchmark

The benchmark program measures all four versions with one generic function. The full program also measures the caches of chapter 13, and is listed there. This is the part that measures the lists.

Listing 9.13 The list benchmark (lines 160 to 236). benchmarking_examples/benchmark.rs

use std::{
    hint::black_box,
    time::{Duration, Instant},
};

use systems_lab::{
    cache::{Cache, arena::LruCache as ArenaCache, rc_list::LruCache as RcCache},
    lists::{SinglyList, boxed, boxed_drop, enum_drop, enum_node},
};

// ---------------------------------------------------------------------------
// Lists: four variants, one loop
// ---------------------------------------------------------------------------

fn list_benchmark(variant: Option<&str>, elements: usize) {
    println!(
        "Singly linked list: push {} values, pop them back in order, then drop a full list",
        with_thousands(elements as u64)
    );
    println!("Best of {LIST_RUNS} runs per variant, allocator warmed up.\n");
    println!(
        "  {:<10} {:>12} {:>13} {:>13}",
        "variant", "elements", "push", "drop"
    );
    println!("  {}", "-".repeat(52));

    match variant {
        Some("box") => run_list::<boxed::LinkedList<u64>>(elements),
        Some("enum") => run_list::<enum_node::LinkedList<u64>>(elements),
        Some("box+drop") => run_list::<boxed_drop::LinkedList<u64>>(elements),
        Some("enum+drop") => run_list::<enum_drop::LinkedList<u64>>(elements),
        _ => {
            run_list::<boxed::LinkedList<u64>>(elements);
            run_list::<enum_node::LinkedList<u64>>(elements);
            run_list::<boxed_drop::LinkedList<u64>>(elements);
            run_list::<enum_drop::LinkedList<u64>>(elements);
        }
    }
}

fn run_list<L: SinglyList<u64>>(elements: usize) {
    // Warm the allocator first: without this the first variant in a process pays
    // for fresh heap pages and looks several times slower than an identical one.
    let mut warm_up = L::new();
    for value in 0..elements as u64 {
        warm_up.push_front(value);
    }
    drop(warm_up);

    let mut best_push = Duration::MAX;
    let mut best_drop = Duration::MAX;

    for _ in 0..LIST_RUNS {
        let mut list = L::new();

        let start = Instant::now();
        for value in 0..elements as u64 {
            list.push_front(value);
        }
        best_push = best_push.min(start.elapsed());

        // Pop every value back and check the order, so a broken list cannot post
        // a fast time.
        let mut expected = elements as u64;
        while let Some(value) = list.pop_front() {
            expected -= 1;
            assert_eq!(value, expected, "{} lost LIFO order", L::variant());
        }
        assert_eq!(expected, 0);
        black_box(expected);

        // Rebuild, then time the drop of a full list. This is where the
        // recursive variants overflow the stack.
        for value in 0..elements as u64 {
            list.push_front(value);
        }
        let start = Instant::now();
        drop(list);
        best_drop = best_drop.min(start.elapsed());
    }

    println!(
        "  {:<10} {:>12} {best_push:>13.2?} {best_drop:>13.2?}",
        L::variant(),
        with_thousands(elements as u64)
    );
}

The full benchmark harness, including the cache benchmarks from Chapter 13, is presented in Listing 13.16.

run_list::<L: SinglyList<u64>> is monomorphized per concrete list type L, ensuring zero dynamic-dispatch overhead during measurement.

The harness enforces three standard microbenchmarking invariants:

  1. Warm-up pass. Initial large allocations trigger kernel demand-paging and allocator pool growth; executing an untimed warm-up pass excludes cold-page faults from the measured window.
  2. Minimum of repeated trials. OS scheduling jitter and background contention can only inflate elapsed time, so the minimum across multiple trials best approximates true algorithmic cost.
  3. Result verification. Each trial pops and validates every element in LIFO order to ensure correctness before accepting a timing measurement.

std::hint::black_box(expected) acts as an optimization barrier, preventing the compiler from eliding the loop via dead-code elimination.

9.9 A doubly linked list

In a doubly linked list, each node stores pointers to both its successor and its predecessor, enabling O(1) insertion and removal at either end as well as bidirectional traversal.

In Rust, this layout introduces shared ownership: every interior node is referenced both by the preceding node’s next link and by the following node’s prev link, which single-owner Box pointers cannot represent.

Wrapping each node in Rc<RefCell<Node<T>>> resolves shared ownership with runtime borrow checking: forward next links hold strong Rc handles defining an acyclic ownership chain from head to tail, while backward prev links hold Weak handles to prevent reference-cycle memory leaks (Figure 9.6).

9.9.1 The types

A node of the doubly linked list has a value and two links. The link forward owns the next node; the link back is weak, so the two directions do not keep each other alive.

Listing 9.14 Type names, the node, and the list (lines 1 to 25). src/bin/ll.rs

// ============================================================================
// Type aliases for clarity.
// ============================================================================
use std::cell::{Ref, RefCell}; // Ref is needed for peek return types
use std::rc::{Rc, Weak};

type NodeRef<T> = Rc<RefCell<Node<T>>>;
type WeakNodeRef<T> = Weak<RefCell<Node<T>>>;

type OptWeakNodeRef<T> = Option<WeakNodeRef<T>>;

// Node and LinkedList definitions.
// ============================================================================

    data: T,
    next: OptNodeRef<T>,
    prev: OptWeakNodeRef<T>,

pub struct LinkedList<T> {

    tail: OptNodeRef<T>,

The full type of a link is Option<Rc<RefCell<Node<T>>>>. It appears in almost every function, so the file names it once, OptNodeRef<T>, with a type alias. The list keeps a head, a tail, and its length.

9.9.2 Adding at either end

A new node at the front must point forward to the old head, and the old head must point back to it. The back of the list works the same way, mirrored.

Listing 9.15 new, len, and push_front (lines 28 to 69).

impl<T> LinkedList<T> {
    /// Creates an empty list.
    pub fn new() -> Self {
        LinkedList {
            head: None,
            tail: None,
            len: 0,
        }
    }

    pub fn len(&self) -> usize {
        self.len
    }
    pub fn is_empty(&self) -> bool {
        self.len == 0
    }

    // --------------------------------------------------------------------
    // push_front
    // --------------------------------------------------------------------
    pub fn push_front(&mut self, data: T) {
        let new_node = Rc::new(RefCell::new(Node {
            data,
            next: None,
            prev: None,
        }));

        // take() moves the old head out of the Option, leaving None.
        match self.head.take() {
            Some(old_head) => {
                // Link old head back to new node (weakly).
                old_head.borrow_mut().prev = Some(Rc::downgrade(&new_node));
                // Link new node forward to old head.
                new_node.borrow_mut().next = Some(old_head);
            }
            None => {
                // List was empty: new node is also the tail.
                self.tail = Some(new_node.clone());
            }
        }
        self.head = Some(new_node);
        self.len += 1;
    }
    // ...
}

push_front creates the new node, then looks at the old head with self.head.take():

  • If there was an old head, its prev becomes a weak link to the new node, made with Rc::downgrade. The new node’s next becomes the old head.
  • If there was no old head, the list was empty, so the new node is also the tail. new_node.clone() makes a second strong handle for tail.

Finally the new node becomes the head, and the length grows by one. borrow_mut() is the RefCell method from section 8.4. Each call is released at the end of its statement, so no two borrows of the same node overlap.

Listing 9.16 push_back (lines 71 to 93).

impl<T> LinkedList<T> {
    // ...
    // --------------------------------------------------------------------
    // push_back
    // --------------------------------------------------------------------
    pub fn push_back(&mut self, data: T) {
        let new_node = Rc::new(RefCell::new(Node {
            data,
            next: None,
            // self.tail.as_ref() gives Option<&NodeRef<T>>,
            // map(Rc::downgrade) turns it into Option<WeakNodeRef<T>>.
            prev: self.tail.as_ref().map(Rc::downgrade),
        }));

        match self.tail.take() {
            Some(old_tail) => {
                old_tail.borrow_mut().next = Some(new_node.clone());
            }
            None => {
                self.head = Some(new_node.clone());
            }
        }
        self.tail = Some(new_node);
        self.len += 1;
    }
    // ...
}

push_back mirrors it at the other end. The new node’s prev is set as it is created: self.tail.as_ref().map(Rc::downgrade). as_ref() turns Option<Rc<...>> into Option<&Rc<...>>, so the tail is looked at without being moved. map(Rc::downgrade) turns that reference into a weak link.

9.9.3 Removing from either end

Removing the front node means unlinking it from its neighbor and moving its value out to the caller.

Listing 9.17 pop_front (lines 95 to 125).

impl<T> LinkedList<T> {
    // ...
    // --------------------------------------------------------------------
    // pop_front
    // --------------------------------------------------------------------
    pub fn pop_front(&mut self) -> Option<T> {
        self.head.take().map(|old_head| {
            // Take ownership of the next node (if any).
            let next = old_head.borrow_mut().next.take();

            match next {
                Some(next_node) => {
                    // Disconnect the new head's prev pointer.
                    next_node.borrow_mut().prev = None;
                    self.head = Some(next_node);
                }
                None => {
                    self.tail = None; // list becomes empty
                }
            }

            self.len -= 1;

            // Safely extract the data. At this point, old_head is the only
            // strong reference (because we removed it from the list and the
            // new head's prev doesn't point to it).
            let node = Rc::try_unwrap(old_head)
                .ok()
                .unwrap()
                .into_inner();
            node.data
        })
    }
    // ...
}

Because pop_front returns an owned T, it must extract the Node<T> from its Rc via Rc::try_unwrap, which succeeds only when the strong reference count equals 1. The method therefore severs every other strong reference before unwrapping:

  1. self.head.take() transfers the list’s strong head handle into old_head.
  2. The successor node’s prev link is cleared to None (a weak link, maintained for structural consistency).
  3. If no successor exists, the list is now empty, so self.tail is cleared to drop the tail’s strong reference.

With old_head holding the sole remaining strong reference, Rc::try_unwrap(old_head) succeeds and .into_inner() consumes the RefCell to yield the owned Node<T>.

The unwrapping chain uses .ok().unwrap() rather than .unwrap() directly because Result::unwrap requires the error type (Rc<RefCell<Node<T>>>) to implement Debug for panic formatting; converting the Result into an Option via .ok() removes the Debug bound on T.

    // --------------------------------------------------------------------
    // pop_back

    pub fn pop_back(&mut self) -> Option<T> {
        self.tail.take().map(|old_tail| {
            // Get the previous node (upgrade the weak reference).
            let prev = old_tail

                .prev

                }
                None => {

                }

                .ok()
                .unwrap()
                .into_inner();
            node.data
        })
    }
    // ...
}

pop_back mirrors pop_front. It follows the weak prev link with upgrade(), which returns None if the previous node is gone, then clears that node’s next.

9.9.4 Looking without removing

Looking at the front value must not move it out of the list. The caller gets a borrow of the value instead.

Listing 9.19 peek_front and peek_back (lines 159 to 180).

impl<T> LinkedList<T> {
    // ...
    // --------------------------------------------------------------------
    // peek_front: returns a guarded reference to the front data.
    // The returned Ref<'_, T> holds the borrow of the RefCell until it goes
    // out of scope, ensuring the reference stays valid.
    // --------------------------------------------------------------------
    pub fn peek_front(&self) -> Option<Ref<'_, T>> {
        // self.head.as_ref() -> Option<&NodeRef<T>>
        self.head.as_ref().map(|node| {
            // node.borrow() returns Ref<'_, Node<T>>.
            // Ref::map projects that to a Ref<'_, T> pointing to the data field.
            Ref::map(node.borrow(), |n| &n.data)
        })
    }

    // --------------------------------------------------------------------
    // peek_back: similar to peek_front.
    // --------------------------------------------------------------------
    pub fn peek_back(&self) -> Option<Ref<'_, T>> {
        self.tail
            .as_ref()
            .map(|node| Ref::map(node.borrow(), |n| &n.data))
    }
}

peek_front returns Option<Ref<'_, T>> rather than Option<&T>. Because the payload resides inside a RefCell, any shared reference remains sound only while the cell’s dynamic borrow guard is active. Ref::map projects the node-level Ref guard onto the data field so callers can dereference *guard safely without exposing internal link fields.

Compared with a singly linked list, this Rc<RefCell<_>> doubly linked list incurs substantial per-node overhead: each node requires an independent heap allocation, strong and weak reference counts, and a dynamic borrow flag checked on every access. It also inherits the recursive Drop vulnerability of Section 9.7 along the strong next chain. Storing nodes contiguously inside a Vec arena and linking them by usize index eliminates both reference-counting overhead and scattered heap allocations.

//! Reverse a singly linked list, and remove nodes from it.
//!
//! Uses `Option<Box<ListNode>>` and a `while let` loop to move pointers in a
//! borrow-safe way. Removal walks a cursor: a mutable borrow of one link.

#[derive(Debug, PartialEq, Eq)]
pub struct ListNode {
    pub val: i32,
    pub next: Option<Box<ListNode>>,
}

impl ListNode {
    pub fn from_slice(values: &[i32]) -> Option<Box<ListNode>> {
        let mut head = None;
        for &value in values.iter().rev() {
            head = Some(Box::new(ListNode {
                val: value,
                next: head,
            }));
        }
        head
    }

    pub fn to_vec(head: Option<Box<ListNode>>) -> Vec<i32> {
        let mut result = Vec::new();
        let mut current = head;
        while let Some(node) = current {
            result.push(node.val);
            current = node.next;
        }
        result
    }
}

pub fn reverse_list(head: Option<Box<ListNode>>) -> Option<Box<ListNode>> {
    let mut previous = None;
    let mut current = head;

    while let Some(mut node) = current {
        current = node.next.take();
        node.next = previous;
        previous = Some(node);
    }

    previous
}

/// Remove every node whose value is `target`, in one pass.
///
/// `cursor` is a mutable borrow of a link: first `head`, then the `next` of
/// each node that stays. A matching node is unlinked by moving its `next` into
/// the link that pointed at it. The cursor does not move after a removal,
/// because the link it holds now points at a node not yet checked.
pub fn remove_all(mut head: Option<Box<ListNode>>, target: i32) -> Option<Box<ListNode>> {
    let mut cursor = &mut head;
    while cursor.is_some() {
        let node = cursor
            .as_mut()
            .expect("checked by is_some");
        if node.val == target {
            let next = node.next.take();
            *cursor = next;
        } else {
            cursor = &mut cursor
                .as_mut()
                .expect("checked by is_some")
                .next;
        }
    }
    head
}

// Singly linked list using an algebraic data type.
//
//    List<T> = Empty
//            | Node { value: T, next: Link<T> }
//
// `Empty` is the end of the list.

type Link<T> = Box<List<T>>;

pub enum List<T> {
    Empty,
    Node { value: T, next: Link<T> },
}

impl<T> List<T> {
    pub fn new() -> Self {
        List::Empty
    }

    pub fn is_empty(&self) -> bool {
        matches!(self, List::Empty)
    }

    pub fn len(&self) -> usize {
        match self {
            List::Empty => 0,
            List::Node { next, .. } => 1 + next.len(),
        }
    }

    /// O(1)
    pub fn push_front(&mut self, value: T) {
        let old = std::mem::replace(self, List::Empty);
        *self = List::Node {
            value,
            next: Link::new(old),
        };
    }

    /// O(1)
    pub fn pop_front(&mut self) -> Option<T> {
        match std::mem::replace(self, List::Empty) {
            List::Empty => None,
            List::Node { value, next } => {
                *self = *next;
                Some(value)
            }
        }
    }
}

fn main() {
    let mut list = List::new();
    list.push_front(2);
    list.push_front(1);
    list.push_front(0);

    assert_eq!(list.len(), 3);
    assert_eq!(list.pop_front(), Some(0));
    assert_eq!(list.pop_front(), Some(1));
    assert_eq!(list.pop_front(), Some(2));
    println!("ok");
}

//! `Option<Box<Node<T>>>`: one heap allocation per node.
//!
//! Pushing takes the old head and boxes it inside the new node. Freeing the head
//! frees its `next`, which frees its `next`, so the drop recurses once per
//! element and overflows the stack on a long list.

use super::SinglyList;

struct Node<T> {
    value: T,
    next: Option<Box<Node<T>>>,
}

pub struct LinkedList<T> {
    head: Option<Box<Node<T>>>,
}

impl<T> SinglyList<T> for LinkedList<T> {
    fn new() -> Self {
        Self { head: None }
    }

    fn push_front(&mut self, value: T) {
        self.head = Some(Box::new(Node {
            value,
            // .take() leaves None in its place and extracts the old head
            next: self.head.take(),
        }));
    }

    fn pop_front(&mut self) -> Option<T> {
        self.head.take().map(|node| {
            // Point the list head to the next node in line
            self.head = node.next;
            // Return the unboxed value
            node.value
        })
    }

    fn is_empty(&self) -> bool {
        self.head.is_none()
    }

    fn variant() -> &'static str {
        "box"
    }
}

//! `Option`. The enum cannot contain itself by value, so the recursive arm holds

    Next(T, Box<ListNode<T>>),

//! `Option<Box<Node<T>>>` with an iterative `Drop`.
//!
//! Push and pop are identical to [`boxed`](super::boxed); only freeing changes.
//! Dropping a node would otherwise drop its `next` and recurse once per element,
//! so the list is unlinked in a loop before any node is freed.

use super::SinglyList;

struct Node<T> {
    value: T,
    next: Option<Box<Node<T>>>,
}

pub struct LinkedList<T> {
    head: Option<Box<Node<T>>>,
}

impl<T> SinglyList<T> for LinkedList<T> {
    fn new() -> Self {
        Self { head: None }
    }

    fn push_front(&mut self, value: T) {
        self.head = Some(Box::new(Node {
            value,
            next: self.head.take(),
        }));
    }

    fn pop_front(&mut self) -> Option<T> {
        self.head.take().map(|node| {
            self.head = node.next;
            node.value
        })
    }

    fn is_empty(&self) -> bool {
        self.head.is_none()
    }

    fn variant() -> &'static str {
        "box+drop"
    }
}

impl<T> Drop for LinkedList<T> {
    fn drop(&mut self) {
        // Walk the chain and unlink each node before it is freed, so no node's
        // drop has to carry the rest of the list on the stack.
        let mut current = self.head.take();
        while let Some(mut node) = current {
            current = node.next.take();
        }
    }
}

// ============================================================================
// Type aliases for clarity.
// ============================================================================
use std::cell::{Ref, RefCell}; // Ref is needed for peek return types
use std::rc::{Rc, Weak};

type NodeRef<T> = Rc<RefCell<Node<T>>>;
type WeakNodeRef<T> = Weak<RefCell<Node<T>>>;
type OptNodeRef<T> = Option<NodeRef<T>>;
type OptWeakNodeRef<T> = Option<WeakNodeRef<T>>;

// ============================================================================
// Node and LinkedList definitions.
// ============================================================================
struct Node<T> {
    data: T,
    next: OptNodeRef<T>,
    prev: OptWeakNodeRef<T>,
}

pub struct LinkedList<T> {
    head: OptNodeRef<T>,
    tail: OptNodeRef<T>,
    len: usize,
}

impl<T> LinkedList<T> {
    /// Creates an empty list.
    pub fn new() -> Self {
        LinkedList {
            head: None,
            tail: None,
            len: 0,
        }
    }

    pub fn len(&self) -> usize {
        self.len
    }
    pub fn is_empty(&self) -> bool {
        self.len == 0
    }

    // --------------------------------------------------------------------
    // push_front
    // --------------------------------------------------------------------
    pub fn push_front(&mut self, data: T) {
        let new_node = Rc::new(RefCell::new(Node {
            data,
            next: None,
            prev: None,
        }));

        // take() moves the old head out of the Option, leaving None.
        match self.head.take() {
            Some(old_head) => {
                // Link old head back to new node (weakly).
                old_head.borrow_mut().prev = Some(Rc::downgrade(&new_node));
                // Link new node forward to old head.
                new_node.borrow_mut().next = Some(old_head);
            }
            None => {
                // List was empty: new node is also the tail.
                self.tail = Some(new_node.clone());
            }
        }
        self.head = Some(new_node);
        self.len += 1;
    }

    // --------------------------------------------------------------------
    // push_back
    // --------------------------------------------------------------------
    pub fn push_back(&mut self, data: T) {
        let new_node = Rc::new(RefCell::new(Node {
            data,
            next: None,
            // self.tail.as_ref() gives Option<&NodeRef<T>>,
            // map(Rc::downgrade) turns it into Option<WeakNodeRef<T>>.
            prev: self.tail.as_ref().map(Rc::downgrade),
        }));

        match self.tail.take() {
            Some(old_tail) => {
                old_tail.borrow_mut().next = Some(new_node.clone());
            }
            None => {
                self.head = Some(new_node.clone());
            }
        }
        self.tail = Some(new_node);
        self.len += 1;
    }

    // --------------------------------------------------------------------
    // pop_front
    // --------------------------------------------------------------------
    pub fn pop_front(&mut self) -> Option<T> {
        self.head.take().map(|old_head| {
            // Take ownership of the next node (if any).
            let next = old_head.borrow_mut().next.take();

            match next {
                Some(next_node) => {
                    // Disconnect the new head's prev pointer.
                    next_node.borrow_mut().prev = None;
                    self.head = Some(next_node);
                }
                None => {
                    self.tail = None; // list becomes empty
                }
            }

            self.len -= 1;

            // Safely extract the data. At this point, old_head is the only
            // strong reference (because we removed it from the list and the
            // new head's prev doesn't point to it).
            let node = Rc::try_unwrap(old_head)
                .ok()
                .unwrap()
                .into_inner();
            node.data
        })
    }

    // --------------------------------------------------------------------
    // pop_back
    // --------------------------------------------------------------------
    pub fn pop_back(&mut self) -> Option<T> {
        self.tail.take().map(|old_tail| {
            // Get the previous node (upgrade the weak reference).
            let prev = old_tail
                .borrow_mut()
                .prev
                .take()
                .and_then(|w| w.upgrade());

            match prev {
                Some(prev_node) => {
                    prev_node.borrow_mut().next = None;
                    self.tail = Some(prev_node);
                }
                None => {
                    self.head = None; // list becomes empty
                }
            }

            self.len -= 1;

            let node = Rc::try_unwrap(old_tail)
                .ok()
                .unwrap()
                .into_inner();
            node.data
        })
    }

    // --------------------------------------------------------------------
    // peek_front: returns a guarded reference to the front data.
    // The returned Ref<'_, T> holds the borrow of the RefCell until it goes
    // out of scope, ensuring the reference stays valid.
    // --------------------------------------------------------------------
    pub fn peek_front(&self) -> Option<Ref<'_, T>> {
        // self.head.as_ref() -> Option<&NodeRef<T>>
        self.head.as_ref().map(|node| {
            // node.borrow() returns Ref<'_, Node<T>>.
            // Ref::map projects that to a Ref<'_, T> pointing to the data field.
            Ref::map(node.borrow(), |n| &n.data)
        })
    }

    // --------------------------------------------------------------------
    // peek_back: similar to peek_front.
    // --------------------------------------------------------------------
    pub fn peek_back(&self) -> Option<Ref<'_, T>> {
        self.tail
            .as_ref()
            .map(|node| Ref::map(node.borrow(), |n| &n.data))
    }
}

// ============================================================================
// Demonstration with main().
// ============================================================================
fn main() {
    let mut list = LinkedList::new();

    list.push_front(10);
    list.push_front(20);
    list.push_back(30);
    list.push_back(40);

    println!("Length: {}", list.len());

    // Peek returns a Ref; we can dereference it with *.
    if let Some(front) = list.peek_front() {
        println!("Front: {}", *front);
    }
    if let Some(back) = list.peek_back() {
        println!("Back: {}", *back);
    }

    println!("Pop front: {:?}", list.pop_front()); // 20
    println!("Pop back:  {:?}", list.pop_back()); // 40

    // Drain the list.
    while let Some(val) = list.pop_front() {
        println!("Popped: {}", val);
    }
    println!("Empty? {}", list.is_empty());
}

// ============================================================================
// Explanation of key methods used:
//
// - Rc::new / RefCell::new        : create a reference-counted, mutable cell.
// - borrow() / borrow_mut()       : borrow the RefCell's contents (immutably/mutably).
// - Rc::downgrade()               : turn an Rc into a Weak (no ownership).
// - Weak::upgrade()               : attempt to get an Rc from a Weak (returns Option).
// - Option::take()                : take the value out of an Option, leaving None.
// - Option::as_ref()              : convert Option<T> to Option<&T> without moving.
// - Option::map()                 : apply a function to the inner value if Some.
// - Option::and_then()            : like map but returns an Option (for chaining).
// - Rc::try_unwrap()              : move the value out of the Rc if it's the only strong ref.
// - Ref::map()                    : project a Ref to a subfield, keeping the borrow alive.
// ============================================================================

Summary

  • A linked list allocates each element in an independent node connected by pointers, providing O(1) head insertion and deletion at the cost of O(i) indexed traversal and poor spatial locality.
  • Option::take and std::mem::replace transfer ownership out of borrowed locations while atomically installing a valid replacement value.
  • In-place list reversal rewires links in O(n) time and O(1) space using three ownership transfers per node.
  • Cursor-based deletion maintains a &mut Option<Box<ListNode>> reference to the owning link, unifying head and interior removal without skipping consecutive matches.
  • Both Option<Box<Node<T>>> and recursive enum layouts benefit from null-pointer niche optimization (16 bytes per u64 node), though the enum layout copies twice as many inline bytes per push.
  • Default compiler-generated drop glue recurses linearly down the next chain and overflows the call stack on long lists; a custom iterative Drop implementation reduces stack usage to O(1).
  • Reliable microbenchmarks perform a warm-up pass, take the minimum across multiple trials, verify output correctness, and guard against dead-code elimination with std::hint::black_box.
  • A safe doubly linked list in Rust pairs Rc<RefCell<Node<T>>> forward links with Weak backward links to prevent reference cycles.
