Cracking the Systems Programming Interview

Trees and tries

This chapter covers

  • The vocabulary of trees: root, leaf, child, subtree, depth
  • A binary tree as an enum, and the three depth-first visiting orders
  • Binary search trees: insert, search, remove, and range queries, written two ways
  • Trees with any number of children: depth-first and breadth-first visits, and grouping by level
  • Saving a tree to a file and loading it back
  • A trie, a tree for finding words by their first letters

A tree is a connected, acyclic hierarchical data structure composed of nodes organized under a strict single-parent relation. Whereas a linear sequence restricts each element to at most one successor, a tree permits each node to own an arbitrary or bounded collection of descendant nodes, termed its children. This topology models hierarchical domains directly, including filesystem directory hierarchies, abstract syntax trees (ASTs), and ordered search structures.

Because every non-root node has a unique parent and no directed cycles exist, a tree exhibits strict single ownership. In Rust, each parent node can own its children directly through Box or Vec without requiring reference counting (Rc) or runtime interior mutability (RefCell). The primary implementation challenges instead concern mutating recursive enum variants in place under the borrow checker and selecting between call-stack recursion and explicit heap-allocated traversal frontiers.

This chapter formalizes core tree terminology and develops four foundational structures: recursive binary trees, binary search trees (BSTs), general k-ary trees with level-order and serialized representations, and prefix tries.

11.1 Tree vocabulary

The structural components of a tree are labeled in Figure 11.1.

  • The root is the unique node with no parent; trees are conventionally drawn with the root at the top.
  • A leaf is a node with no children.
  • The subtree rooted at a node consists of that node and all of its descendants. Because every subtree is itself a tree, tree algorithms naturally admit recursive definitions.
  • The depth of a tree is the number of levels along the longest path from the root down to a leaf.

A binary tree restricts each node to at most two children, designated the left child and the right child.

11.2 A binary tree as an enum

A binary tree is defined inductively as either empty or a node holding a value together with two smaller binary trees. This definition translates directly into a Rust enum:

Listing 11.1 The tree type (lines 1 to 16). src/problems/binary_tree.rs

//! Binary tree as an algebraic data type.
//!
//! ```text
//! Tree = Empty
//!      | Node { value, left: Box<Tree>, right: Box<Tree> }
//! ```

#[derive(Debug, Clone, PartialEq, Eq)]
pub enum Tree {
    Empty,
    Node {
        value: i32,
        left: Box<Tree>,
        right: Box<Tree>,
    },
}

Each child pointer must be wrapped in Box<Tree> to introduce heap indirection. Embedding Tree values inline within Tree::Node produces a recursive type of unbounded static size, which the compiler rejects because stack frame allocation requires a known, finite Sized layout. Boxing each child reduces the inline representation of a node to a fixed-size discriminant, its scalar payload, and two machine-word pointers.

11.2.1 Depth and inversion

Listing 11.2 Depth and inversion (lines 19 to 35).

impl Tree {
    pub fn max_depth(&self) -> usize {
        match self {
            Tree::Empty => 0,
            Tree::Node { left, right, .. } => 1 + left.max_depth().max(right.max_depth()),
        }
    }

    pub fn invert(&mut self) {
        match self {
            Tree::Empty => {}
            Tree::Node { left, right, .. } => {
                left.invert();
                right.invert();
                std::mem::swap(left, right);
            }
        }
    }
    // ...
}

Each method dispatches on the two variants of Tree. The Empty arm serves as the base case, returning an answer directly without further recursion, while the Node arm recurses on both subtrees and combines their results.

The max_depth method mirrors the recursive definition directly: an empty tree has depth 0, and a non-empty node has depth 1 plus the greater depth of its two subtrees. In Figure 11.1, the leaves have depth 1, node 20 has depth 2, and the root has depth 3.

The invert method transforms the tree into its mirror image by recursively inverting both subtrees and then exchanging them with std::mem::swap(left, right). Because the match pattern binds left and right as mutable references to the Box handles, the swap exchanges two pointers in place without moving node payloads.

11.2.2 The three depth-first orders

Visiting every node of a tree exactly once is called a traversal. Descending along one branch as far as possible before backtracking is a depth-first traversal. The three standard depth-first orders differ only in when a node is visited relative to its children (Figure 11.2).

  • Pre-order visits the node first, then its left subtree, then its right subtree.
  • In-order visits the left subtree, then the node, then the right subtree.
  • Post-order visits both subtrees, then the node.

Each public method allocates a single Vec, passes a mutable reference to a private recursive helper, and returns the populated vector. Accumulating into one buffer avoids allocating intermediate vectors at every node.

                left.collect_inorder(out);

                right.collect_inorder(out);
            }
        }
    }

    fn collect_postorder(&self, out: &mut Vec<i32>) {
        match self {
            Tree::Empty => {}

The three helpers are structurally identical, differing only in where out.push(*value) appears relative to the two recursive calls. Dereferencing *value copies the i32 payload out of the shared reference.

11.3 Binary search trees

A binary search tree (BST) is a binary tree that enforces a strict ordering invariant: for every node, all values in its left subtree are smaller than the node’s value, and all values in its right subtree are larger.

This invariant accelerates lookup. Comparing the target against the current node determines which subtree can contain it: smaller targets lie exclusively in the left subtree, and larger targets lie exclusively in the right. Each comparison eliminates an entire subtree from consideration (Figure 11.3).

Two implementations of the same BST interface follow. Both share identical insertion and lookup logic, differing in how they handle node deletion and range-query allocation. The first implementation is examined in full; the second isolates the structural and allocation trade-offs.

11.3.1 The type, insertion, and search

Listing 11.6 The type (lines 1 to 14). src/bin/bst_clean.rs

use std::cmp::Ordering;

type TreeLink<T> = Box<BST<T>>;

#[derive(Debug, Clone, Default)]
pub enum BST<T> {
    #[default]
    Empty,
    Node {
        value: T,
        left: TreeLink<T>,
        right: TreeLink<T>,
    },
}

BST<T> is generic over its element type, and its methods require T: Ord so that values admit a total ordering. Annotating Empty with #[default] designates the empty tree as the default value, which the removal logic relies on.

Listing 11.7 Creating, inserting, and searching (lines 17 to 47).

impl<T: Ord> BST<T> {
    pub fn new() -> Self {
        Self::Empty
    }

    pub fn insert(&mut self, val: T) {
        match self {
            Self::Empty => {
                *self = Self::Node {
                    value: val,
                    left: Box::new(Self::Empty),
                    right: Box::new(Self::Empty),
                };
            }
            Self::Node { value, left, right } => match val.cmp(value) {
                Ordering::Less => left.insert(val),
                Ordering::Greater => right.insert(val),
                Ordering::Equal => {}
            },
        }
    }

    pub fn contains(&self, val: &T) -> bool {
        match self {
            Self::Empty => false,
            Self::Node { value, left, right } => match val.cmp(value) {
                Ordering::Less => left.contains(val),
                Ordering::Greater => right.contains(val),
                Ordering::Equal => true,
            },
        }
    }
    // ...
}

insert takes &mut self to mutate the tree in place, descending recursively until it reaches an Empty slot and replacing it with a new leaf via *self = Self::Node { ... }. At each internal node, val.cmp(value) returns Ordering::Less, Greater, or Equal. Duplicate values are ignored, so the tree maintains set semantics. The contains method follows the identical search path without modifying the tree.

11.3.2 Removal

Removing a value is the most intricate BST operation because the ordering invariant must be preserved across three structural cases (Figure 11.4).

  1. No left child. Promote the right subtree into the removed node’s position.
  2. No right child. Promote the left subtree into the removed node’s position.
  3. Two children. Retain the structural node and overwrite its payload with its in-order successor, defined as the minimum element in its right subtree. Because this successor exceeds every key in the left subtree and is strictly less than all remaining keys in the right subtree, the BST ordering invariant is preserved. The successor node is then deleted from the right subtree; having no left child by definition, its removal reduces immediately to Case 1.

Listing 11.8 Removal (lines 49 to 90).

impl<T: Ord> BST<T> {
    // ...
    pub fn remove(&mut self, val: &T) -> bool {
        match self {
            Self::Empty => false,
            Self::Node { value, left, right } => match val.cmp(value) {
                Ordering::Less => left.remove(val),
                Ordering::Greater => right.remove(val),
                Ordering::Equal => {
                    if left.is_empty() && right.is_empty() {
                        *self = Self::Empty;
                        return true;
                    }
                    if left.is_empty() {
                        *self = *std::mem::take(right);
                        return true;
                    }
                    if right.is_empty() {
                        *self = *std::mem::take(left);
                        return true;
                    }
                    let min_val = right.remove_min().unwrap();
                    *value = min_val;
                    true
                }
            },
        }
    }

    fn remove_min(&mut self) -> Option<T> {
        match self {
            Self::Empty => None,
            Self::Node { left, .. } if left.is_empty() => {
                let node = std::mem::take(self);
                if let Self::Node { value, right, .. } = node {
                    *self = *right;
                    Some(value)
                } else {
                    unreachable!()
                }
            }
            Self::Node { left, .. } => left.remove_min(),
        }
    }
    // ...
}

The first two cases replace *self with one of its own children. Because right is a mutable reference borrowing *self, moving a subtree out through right and assigning it directly to *self in one step is rejected by the borrow checker. Calling std::mem::take(right) resolves this conflict by moving the subtree out and leaving BST::Empty (the Default value) in its place. The assignment *self = *std::mem::take(right) then unboxes the moved subtree and installs it at *self.

The implementation also handles a leaf (a node with no children) in its own arm, although case 1 already covers it.

For case 3, remove_min extracts and returns the smallest value in the right subtree. It descends left until the match guard Self::Node { left, .. } if left.is_empty() identifies the leftmost node. Taking that node out with std::mem::take(self) allows installing its right subtree in its place and returning its value. The if let ... else { unreachable!() } branch satisfies the compiler, which cannot statically prove that the value taken inside a Node arm is itself a Node; unreachable!() panics if that invariant were ever violated.

remove returns true when the target value was found and removed, and false otherwise, allowing callers to distinguish deletion from a missing key.

11.3.3 Range queries

A range query returns every value within a closed interval [low, high] in sorted order, pruning subtrees that cannot contain matching elements.

Listing 11.9 Range queries (lines 92 to 114).

impl<T: Ord> BST<T> {
    // ...
    pub fn range(&self, low: &T, high: &T) -> Vec<&T> {
        let mut result = Vec::new();
        self.range_helper(low, high, &mut result);
        result
    }

    // Explicit lifetime 'a ties the references in the vector to the lifetime of &self.
    fn range_helper<'a>(&'a self, low: &T, high: &T, acc: &mut Vec<&'a T>) {
        match self {
            Self::Empty => {}
            Self::Node { value, left, right } => {
                if value < low {
                    right.range_helper(low, high, acc);
                } else if value > high {
                    left.range_helper(low, high, acc);
                } else {
                    left.range_helper(low, high, acc);
                    acc.push(value);
                    right.range_helper(low, high, acc);
                }
            }
        }
    }
    // ...
}

range_helper appends matching element references into an accumulator acc, exploiting the BST ordering invariant to prune unreachable subtrees across three mutually exclusive branches:

  • When the node’s key is strictly less than low, every key in its left subtree is also below low; traversal prunes the left subtree and descends exclusively into the right subtree.
  • When the node’s key exceeds high, every key in its right subtree also exceeds high; traversal prunes the right subtree and descends exclusively into the left subtree.
  • When the key falls within [low, high], the helper visits the left subtree, records the current key, and visits the right subtree. Performing this visit in-order guarantees monotonically ascending output without a post-pass sort.

The method signature declares an explicit lifetime parameter: fn range_helper<'a>(&'a self, ..., acc: &mut Vec<&'a T>). Every reference pushed into acc borrows from the underlying tree storage and must therefore share the borrow lifetime 'a of &'a self. Under Rust’s default lifetime elision rules, omitting 'a assigns distinct anonymous lifetimes to &self and the vector’s element references, causing the borrow checker to reject the insertion into acc.

11.3.4 A second BST, with an iterative minimum

The second implementation adopts alternative strategies for removal and range queries.

Listing 11.11 Removal and pop_min (lines 49 to 84). src/bin/bst_easy.rs

use std::{
    cmp::Ordering::{Equal, Greater, Less},
    mem,
};

impl<T: Ord> BST<T> {
    // ...
    pub fn remove(&mut self, val: &T) {
        match self {
            Self::Empty => {}
            Self::Node { value, left, right } => match val.cmp(value) {
                Less => left.remove(val),
                Greater => right.remove(val),
                Equal => {
                    if left.is_empty() {
                        *self = right.take();
                    } else if right.is_empty() {
                        *self = left.take();
                    } else {
                        *value = right.pop_min().unwrap();
                    }
                }
            },
        }
    }

    pub fn pop_min(&mut self) -> Option<T> {
        let mut node = self;

        while node.has_left() {
            if let Self::Node { left, .. } = node {
                node = left;
            }
        }

        match node.take() {
            Self::Empty => None,
            Self::Node { value, right, .. } => {
                *node = *right;
                Some(value)
            }
        }
    }
    // ...
}

This remove implementation delegates extraction to a helper method take (defined at the end of the module) that substitutes BST::Empty via mem::replace, eliminating the Default trait bound on BST<T>. Method resolution dereferences Box<BST<T>> automatically, allowing right.take() to extract the owned child subtree directly.

Rather than descending recursively, pop_min locates the minimum element iteratively by advancing a mutable cursor reference node down the left spine of the tree:

let mut node = self;
while node.has_left() {
    if let Self::Node { left, .. } = node {
        node = left;
    }
}

Upon loop termination, node refers to the leftmost node. Matching on node.take() extracts its value and promotes its right subtree without requiring an unreachable!() guard. Because this loop operates in O(1) auxiliary stack space regardless of tree height, it eliminates stack-overflow risk on degenerate trees. Exposing pop_min as a public method additionally enables the BST to function as a min-ordered priority structure.

Listing 11.12 A range query that returns a new vector (lines 86 to 102).

impl<T: Ord> BST<T> {
    // ...
    pub fn range(&self, from: &T, to: &T) -> Vec<&T> {
        let mut result = Vec::new();

        if let Self::Node { value, left, right } = self {
            if from < value {
                result.extend(left.range(from, to));
            }
            if from <= value && value <= to {
                result.push(value);
            }
            if value < to {
                result.extend(right.range(from, to));
            }
        }

        result
    }
    // ...
}

This range implementation allocates a fresh Vec per recursive invocation and merges child results via extend. Although more concise than the accumulator pattern in Listing 11.9, it incurs O(k) heap allocations across k visited nodes, whereas passing a shared &mut Vec accumulator performs a single amortized allocation.

    Empty,
    Node {
        value: T,
        left: Box<BST<T>>,
        right: Box<BST<T>>,
    },
}

impl<T: Ord> BST<T> {
    pub fn new() -> Self {
        Self::Empty
    }

    pub fn insert(&mut self, val: T) {
        match self {
            Self::Empty => {
                *self = Self::Node {
                    value: val,
                    left: Box::new(Self::Empty),
                    right: Box::new(Self::Empty),
                };
            }
            Self::Node { value, left, right } => match val.cmp(value) {
                Less => left.insert(val),
                Greater => right.insert(val),
                Equal => {}
            },
        }
    }

    pub fn contains(&self, val: &T) -> bool {
        match self {
            Self::Empty => false,
            Self::Node { value, left, right } => match val.cmp(value) {
                Less => left.contains(val),
                Greater => right.contains(val),
                Equal => true,
            },
        }
    }

    pub fn remove(&mut self, val: &T) {
        match self {
            Self::Empty => {}
            Self::Node { value, left, right } => match val.cmp(value) {
                Less => left.remove(val),
                Greater => right.remove(val),
                Equal => {
                    if left.is_empty() {
                        *self = right.take();
                    } else if right.is_empty() {
                        *self = left.take();
                    } else {
                        *value = right.pop_min().unwrap();
                    }
                }
            },
        }
    }

    pub fn pop_min(&mut self) -> Option<T> {
        let mut node = self;

        while node.has_left() {
            if let Self::Node { left, .. } = node {
                node = left;
            }
        }

        match node.take() {
            Self::Empty => None,
            Self::Node { value, right, .. } => {
                *node = *right;
                Some(value)
            }
        }
    }

    pub fn range(&self, from: &T, to: &T) -> Vec<&T> {
        let mut result = Vec::new();

        if let Self::Node { value, left, right } = self {
            if from < value {
                result.extend(left.range(from, to));
            }
            if from <= value && value <= to {
                result.push(value);
            }
            if value < to {
                result.extend(right.range(from, to));
            }
        }

        result
    }

    fn is_empty(&self) -> bool {
        match self {
            Self::Empty => true,
            Self::Node { .. } => false,
        }
    }

    fn has_left(&self) -> bool {
        match self {
            Self::Empty => false,
            Self::Node { left, .. } => !left.is_empty(),
        }
    }

    fn take(&mut self) -> Self {
        mem::replace(self, Self::Empty)
    }
}

fn main() {
    let mut bst = BST::new();

    bst.insert(10);
    bst.insert(5);
    bst.insert(15);
    bst.insert(3);
    bst.insert(7);
    bst.insert(12);

    println!("Contains 7: {}", bst.contains(&7));
    println!("Range 4 to 12: {:?}", bst.range(&4, &12));

    bst.remove(&10);
    println!("After removing 10: {:?}", bst.range(&0, &100));

    println!("Pop min: {:?}", bst.pop_min());
    println!("{:#?}", bst);
}

WARNING: Neither implementation performs self-balancing. Inserting keys in strictly ascending order (1, 2, 3, and so on) appends each value as the right child of the previous node, degenerating the tree into a linear chain of depth n. Lookups then degrade to O(n), and every recursive method consumes O(n) stack frames. For balanced search trees in production code, use the standard library’s BTreeMap.

11.4 Trees with any number of children

Many hierarchical structures are not binary; a filesystem directory, for example, can hold an arbitrary number of entries. Modeling a node with a Vec<TreeNode<T>> of children accommodates arbitrary branching without requiring Box, because Vec already heap-allocates its backing buffer and keeps the node’s inline size fixed.

11.4.1 Depth first and breadth first

The two fundamental traversal strategies for a multi-way tree are illustrated in Figure 11.5. A depth-first traversal descends completely down one branch before starting the next (as in Section 11.2.2), whereas a breadth-first traversal visits nodes level by level: the root, then all of its children, then all of their children.

Depth-first traversal maps naturally onto recursion, whereas breadth-first traversal requires a FIFO queue. The root is enqueued first; on each iteration, the front node is dequeued, visited, and its children are appended to the back. Because children always enter at the back, every node of one level leaves the queue before any node of the next level is processed.

Each node owns its payload together with a contiguous Vec<TreeNode<T>> of child nodes. Because Vec stores its elements in a heap-allocated array, storing children inline within the vector permits unbounded arity while improving spatial cache locality during sibling iteration:

use std::collections::VecDeque;

struct TreeNode<T> {
    value: T,
    children: Vec<TreeNode<T>>, // Owned children directly inline
}

    pub fn bfs(&self) {

        while let Some(node) = queue.pop_front() {
            println!("{}", node.value);

            for child in &node.children {
                queue.push_back(child);
            }
        }
    }
}

11.4.2 Grouping values by level

A standard breadth-first variant partitions node values by depth, returning a nested sequence (Vec<Vec<&T>>) in which index d contains all nodes at distance d from the root. The module below presents two equivalent formulations.

Listing 11.15 The type and the first version (lines 1 to 20). src/bin/tree_under_pressure.rs

use std::collections::VecDeque;

#[derive(Debug)]
struct TreeNode<T> {
    value: T,
    children: Vec<TreeNode<T>>,
}

fn level_order<T>(root: &TreeNode<T>) -> Vec<Vec<&T>> {
    let mut result = Vec::new();
    let mut level = vec![root];
    while !level.is_empty() {
        result.push(level.iter().map(|n| &n.value).collect());
        level = level
            .iter()
            .flat_map(|n| &n.children)
            .collect();
    }
    result
}

level_order materializes one complete frontier per iteration inside level: Vec<&TreeNode<T>>. Each pass projects the current frontier’s payloads into the output vector and constructs the succeeding frontier via level.iter().flat_map(|n| &n.children).collect(), flattening all child slices into a single contiguous buffer. Iteration terminates when the frontier becomes empty.

Listing 11.16 The second version, with a queue (lines 22 to 40).

fn level_order_readable<T>(root: &TreeNode<T>) -> Vec<Vec<&T>> {
    let mut result = Vec::new();
    let mut queue = VecDeque::from([(root)]);

    while !queue.is_empty() {
        let current_size = queue.len();
        let mut level = Vec::with_capacity(current_size);

        for _ in 1..=current_size {
            let Some(node) = queue.pop_front() else { break };

            level.push(&node.value);
            queue.extend(&node.children);
        }

        result.push(level);
    }
    result
}

level_order_readable maintains a single VecDeque frontier. The loop invariant relies on snapshotting queue.len() at the start of each outer iteration: at that boundary, the queue contains exclusively the nodes of the current depth. The inner loop dequeues exactly that count, records each payload, and appends child references at the back for the subsequent depth.

The statement let Some(node) = queue.pop_front() else { break }; employs Rust’s let-else syntax, binding node when the refutable pattern matches and executing the diverging else branch otherwise. Calling queue.extend(&node.children) enqueues all child references in a single batch.

11.5 Saving a tree to a file and loading it back

Persisting a tree to storage requires converting its hierarchical structure into a flat sequence of text, a process called serialization, so that the exact topology can be reconstructed later.

A pre-order sequence of values alone cannot uniquely identify a multi-way tree because it omits where each node’s children terminate. Appending each node’s child count immediately after its value resolves this ambiguity (Figure 11.6): a deserializer reads a value and its child count k, then recursively reads k child subtrees.

Listing 11.18 The tree type, and writing the pairs (lines 1 to 47). src/bin/tree_serializ_deserialize_into_file.rs

use std::{collections::VecDeque, fs, io, str::FromStr};

#[derive(Debug)]
struct TreeNode<T> {
    value: T,
    children: Vec<TreeNode<T>>,
}

impl<T> TreeNode<T> {
    // ...
    fn serialize(&self) -> Vec<String>
    where
        T: ToString,
    {
        let mut serialized = Vec::new();
        let mut stack = vec![self];

        while let Some(node) = stack.pop() {
            serialized.push(node.value.to_string());
            serialized.push(node.children.len().to_string());

            for child in node.children.iter().rev() {
                stack.push(child);
            }
        }

        serialized
    }
    // ...
}

TreeNode<T> retains the multi-way representation of Section 11.4, pairing a generic payload with a Vec of child nodes.

serialize performs an iterative pre-order traversal backed by an explicit heap-allocated stack (Vec). Pushing children in reverse order via iter().rev() ensures that the leftmost child resides at the top of the stack and is popped first, matching recursive pre-order visitation. For each visited node, the encoder emits two string tokens: the formatted payload and its arity (child count).

Placing the where T: ToString bound directly on serialize rather than on the enclosing impl<T> block keeps the container type unconstrained while restricting serialization exclusively to string-formattable payloads.

Listing 11.19 Reading the pairs back (lines 49 to 63).

impl<T> TreeNode<T> {

    where
        T: FromStr,
    {
        let value = serialized.get(*pos)?.parse().ok()?;
        let child_count: usize = serialized.get(*pos + 1)?.parse().ok()?;
        *pos += 2;

        let mut children = Vec::new();
        for _ in 0..child_count {

        }

        Some(TreeNode { value, children })
    }
    // ...
}

deserialize reconstructs the tree recursively using a shared cursor pos: &mut usize into the flat token slice. Each invocation reads the (value, child_count) pair at *pos, advances *pos by two, and recurses child_count times to rebuild every child subtree in order.

Every fallible step propagates failure through the ? operator on Option: a truncated token stream, an unparseable value, or a non-numeric child count. Calling .parse().ok()? converts the Result from parse into an Option, causing any malformed input to return None.

#[derive(Debug)]
struct TreeNode<T> {
    value: T,
    children: Vec<TreeNode<T>>,
}

impl<T> TreeNode<T> {
    fn level_order(&self) -> Vec<Vec<&T>> {
        let mut result = Vec::new();
        let mut queue = VecDeque::from([self]);

        while !queue.is_empty() {
            let current_size = queue.len();
            let mut level = Vec::with_capacity(current_size);

            for _ in 1..=current_size {
                let Some(node) = queue.pop_front() else { break };
                level.push(&node.value);
                queue.extend(&node.children);
            }

            result.push(level);
        }

        result
    }

    fn serialize(&self) -> Vec<String>
    where
        T: ToString,
    {
        let mut serialized = Vec::new();
        let mut stack = vec![self];

        while let Some(node) = stack.pop() {
            serialized.push(node.value.to_string());
            serialized.push(node.children.len().to_string());

            for child in node.children.iter().rev() {
                stack.push(child);
            }
        }

        serialized
    }

    fn deserialize(serialized: &[String], pos: &mut usize) -> Option<Self>
    where
        T: FromStr,
    {
        let value = serialized.get(*pos)?.parse().ok()?;
        let child_count: usize = serialized.get(*pos + 1)?.parse().ok()?;
        *pos += 2;

        let mut children = Vec::new();
        for _ in 0..child_count {
            children.push(Self::deserialize(serialized, pos)?);
        }

        Some(TreeNode { value, children })
    }

    where
        T: ToString,

    }

        let serialized: Vec<String> = text.lines().map(String::from).collect();

    }

11.6 A trie for finding words by prefix

A trie (derived from retrieval, commonly pronounced “try”) is a prefix tree that indexes a set of strings by factoring out shared leading character sequences. Each directed edge represents a single character transition; traversing from the root along the characters of a key locates its corresponding node, where a boolean flag indicates whether a complete stored key terminates at that position (Figure 11.7).

A prefix is any leading substring of a string; for instance, "gp" is a prefix of "gpu". Because every descendant of a node shares the path leading to that node, a trie answers prefix-membership queries by following the prefix’s character transitions from the root, making it the foundational index for autocompletion, routing tables, and lexical dictionaries.

A trie encapsulates a single root Node. Each Node stores a transition table mapping characters to owned child nodes along with a terminal marker indicating key termination:

pub struct Trie {
    root: Node,
}

#[derive(Default)]
struct Node {
    children: HashMap<char, Node>,
    terminal: bool,
}

Listing 11.21 The complete file. src/problems/trie.rs

//! Trie / prefix tree.
//!
//! Used for autocomplete, command completion, and prefix matching.

use std::collections::HashMap;

#[derive(Default)]
pub struct Trie {
    root: Node,
}

#[derive(Default)]
struct Node {
    children: HashMap<char, Node>,
    terminal: bool,
}

impl Trie {
    pub fn new() -> Self {
        Self::default()
    }

    pub fn insert(&mut self, word: &str) {
        let mut node = &mut self.root;
        for ch in word.chars() {
            node = node.children.entry(ch).or_default();
        }
        node.terminal = true;
    }

    pub fn search(&self, word: &str) -> bool {
        self.find_node(word)
            .is_some_and(|node| node.terminal)
    }

    pub fn starts_with(&self, prefix: &str) -> bool {
        self.find_node(prefix).is_some()
    }

    fn find_node(&self, word: &str) -> Option<&Node> {
        let mut node = &self.root;
        for ch in word.chars() {
            node = node.children.get(&ch)?;
        }
        Some(node)
    }
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn trie_insert_search_and_prefix() {
        let mut trie = Trie::new();
        trie.insert("gpu");
        trie.insert("gpucloud");

        assert!(trie.search("gpu"));
        assert!(trie.search("gpucloud"));
        assert!(!trie.search("gp"));
        assert!(!trie.search("gpucloudapi"));

Each Node stores a HashMap<char, Node> for outgoing transitions and a boolean terminal flag. Deriving Default on both types allows empty nodes to be instantiated directly via Node::default().

insert advances a mutable cursor node through the character sequence, creating intermediate nodes on demand:

node = node.children.entry(ch).or_default();

entry(ch).or_default() performs a single hash lookup, returning a mutable reference to the existing child or inserting a default Node if none is present. Rebinding node descends one level; once all characters are consumed, setting node.terminal = true registers the complete key.

find_node executes the corresponding read-only descent: node.children.get(&ch)? short-circuits and returns None upon encountering any absent transition. search verifies both node existence and termination via is_some_and(|n| n.terminal), whereas starts_with tests only whether the prefix path resolves to a valid node.

Searching for a word of m characters requires m steps, independent of the total number of stored words. Storing a HashMap per node supports arbitrary Unicode characters at the cost of significant per-node memory overhead. When the alphabet is restricted to lowercase ASCII letters, a fixed array of 26 child pointers per node reduces both memory footprint and lookup latency.

Summary

  • A tree is a connected, acyclic hierarchy of nodes. Because every subtree is itself a tree, tree algorithms admit direct inductive and recursive formulations.
  • A binary tree maps cleanly onto a Rust enum with Box-indirected children. Pre-order, in-order, and post-order traversals differ only in when a node is visited relative to its left and right subtrees.
  • A binary search tree enforces a total ordering invariant across left and right subtrees, pruning half the remaining search space per comparison in balanced topologies.
  • BST deletion resolves three structural cases; the two-child case substitutes the in-order successor (minimum of the right subtree) and deletes that successor via Case 1.
  • std::mem::take and std::mem::replace enable in-place replacement of *self with an owned child subtree without violating borrow-checker exclusivity.
  • Range queries prune subtrees outside [low, high] and traverse qualifying subtrees in-order to yield sorted output.
  • General k-ary trees store children in a contiguous Vec. Breadth-first level partitioning tracks depth boundaries either by swapping frontier vectors or by snapshotting queue.len() at each level.
  • Pre-order traversal paired with per-node child counts encodes a multi-way tree unambiguously for lossless deserialization.
  • A trie factors common prefixes across keys, executing exact lookup and prefix queries in O(m) time independent of dictionary cardinality.
